# Application sharing media prototype

These assets implement `boss-app-share/1` independently of terminal sharing.
They are shared by the trusted native browser page, the local external-browser
page, and the authenticated `live-sessions/app-viewer/` web endpoint. The web
bundle is generated by `scripts/sync-app-viewer-assets.mjs`; edit these sources,
then regenerate that bundle.

## Host integration

The host serves the assets on its private loopback resource server and injects
`window.__bossAppShareConfig` before loading the module. Set `autoStart: false`
for a native host page; after installing `window.__bossAppShareBridge`, invoke
`window.BossAppShareHost.start(window.__bossAppShareConfig)`.

Configuration fields:

| Field | Meaning |
| --- | --- |
| `sessionId`, `generation`, `peerId` | Backend registered/admitted identities |
| `windowId` | Explicitly selected native window identity |
| `keyEpoch` | Fresh UUID for every publishing lifetime |
| `mediaRootKey` | 32 random bytes, base64url without padding |
| `hostPublicKey` | Ed25519 public key, base64url SPKI |
| `hostPrivateKey` | Host only: Ed25519 private key, base64url PKCS8 |
| `rpcUrl`, `rpcToken` | Private same-origin loopback RPC capability |
| `apiUrl`, `csrf` | Alternative: same-origin HTTPS cookie/CSRF API |
| `role` | Viewer `view` or `control` admission capability |

Keys and configuration must not be logged. The owner registry is trusted for
key delivery, as in existing terminal account discovery. The private signing
key never leaves the publisher's trusted page. A relay transport cannot read
the pixel-bearing payload, but the owner registry intentionally holds the root
key inside the account-only viewer URL.

The host's local `automaticSharingEnabled` policy defaults to true. After sign-in,
the coordinator publishes the currently visible, registered BossConsole windows;
it never selects a display or another application's window. Saved opt-outs remain
off. Stop pauses automatic sharing until the next sign-in or explicit enable, and
manual window selection is retained for that publication. A new window does not
restart an existing publication. Screen Recording permission is still required.

Cursor feedback is an optional standard CSS shape in signed geometry metadata.
Native cursor changes wake the protected raw-frame reader with a metadata-only
204 response; unchanged pixels are not copied or painted again. Cursor updates
do not change the geometry revision or control lease. Older hosts/viewers continue
without this field. The client applies it only while controlling the stream.

The authenticated hosted viewer returns to its same-origin session list after a
terminal media failure or Disconnect. Transient failures keep their existing
recovery window. Native viewers retain their local disconnect behavior.

Host calls `BossAppShareHost.frame({png,width,height,geometryRevision})` using
standard base64 PNG snapshots from the exactly selected native capture source.
The canvas retains only the latest waiting snapshot, requests one encoded video
frame after drawing, uses the `detail` content hint for text, and never selects
a display or matches a window by title. Quality mode controls await real-media
measurements; no unimplemented automatic-quality selector is exposed.
Call `stop()` when the selected window closes, the account changes, capture is
revoked, the computer locks, or sharing stops. Restart with a fresh generation,
epoch and root; never reuse a publishing cipher after resetting its counter.

The bridge provides `state(json)` and `input(json)` callbacks. When it also
implements `request(id,json)`, resolve a request through
`BossAppShareHost.resolve(id,responseJson)` / `.reject(id)` (the viewer exposes
the same methods). Otherwise requests use the scoped loopback HTTP capability.
State includes `lease` with `{leaseId,peerId,expiresAt}` or `null`. Native input
must independently enforce that verified lease, generation, window, geometry,
sequence, exact scoped target and private-surface exclusions. JavaScript
decryption is not a replacement for the native authority check.

## Transport and encryption

One publisher PeerConnection and one VP8 publication carry a selected window,
regardless of viewer count. Each viewer subscribes through its own SFU connection.
Backend operations serialize Cloudflare session changes and derive SFU track
identities from admission. No provider secret or arbitrary SFU identifier is
accepted by the page. There is no per-viewer P2P publication fallback.

VP8 is the sole negotiated codec. Its 3-byte delta / 10-byte keyframe header is
kept clear for RTP packetization and authenticated as associated data. Each
pixel-bearing encoded payload uses AES-256-GCM with a context-derived HKDF key,
a 64-bit monotonic counter nonce, and an Ed25519 signature by the host. Signatures
prevent an admitted viewer who knows the media root from forging host frames.
The cryptographic context binds protocol, domain, application session,
generation, window and key epoch. A bounded replay window permits media
reordering. Plaintext and unsupported transforms/codecs fail closed.

Subscribers bind the receiver created by the incoming offer, pinned to its
server-authorized video MID, before answering. They require encoded streams so
frames cannot bypass the decryptor during setup. Extra media sections are
refused. Disconnect waits for bounded media/lease cleanup before closing the
API bridge; small HTTP cleanup requests use keepalive for page exit.

The hosted viewer offers the explicitly registered windows by title. Switching
requests a fresh same-account admission, releases the old controller lease and
media subscription, then connects the selected window. It does not focus or
resize the host window. Native viewers receive their selected window from the
host's connections UI. Only the explicit `publication_pending` response is
retried during on-demand startup, with a 30-second retry budget and cancellation
when the viewer closes. Permission and generation failures are never retried.
An ICE disconnect has a ten-second recovery grace; reconnection preserves its
cipher counters but releases control. A peer that stays disconnected closes
its media allocation and stops renewing admission, so it cannot hold capture
demand indefinitely. A later reconnect requires fresh admission.

Control uses a persistent, reliable ordered SFU DataChannel. All viewers can
receive host-signed geometry metadata. The backend grants reply permission only
to the current controller. Commands use an independent random lease secret,
HKDF domain, AES-GCM nonce counter and strictly increasing input sequence.
Only the host and admitted lease holder receive that secret. A lease is renewed
every 10 seconds and expires after 30 seconds; host authority polling once per
second carries lease metadata only, never individual input commands. Native
local takeover must refuse reinstatement of the retired lease. A failure to
verify host session/lease health stops the publisher; restarting requires fresh
media authority rather than continuing an old key indefinitely.

Control plaintext binds session, generation, window, geometry revision, peer,
lease and sequence. Pointer coordinates exclude letterbox bars. The sender
coalesces pending pointer moves, bounds discrete input to 64 queued commands and
the DataChannel buffer to 64 KiB, and relinquishes control on backpressure.
Cipher state is retained if the same lease is temporarily unavailable, so
neither sending nonce counters nor receiving replay history can reset.

## Validation and remaining gates

Run from the repository root:

```sh
node --test composeApp/src/desktopTest/js/app-sharing/*.test.mjs
```

The tests execute WebCrypto and cover ten independent viewers decrypting the
same ciphertext, frame signatures, tampering, context confusion, replay,
control renewal/reacquisition, bounded input, geometry mapping, mocked SFU
lifecycle, latest-only snapshots, and cookie/CSRF bootstrap. This is not a real
ten-viewer load test or a real WebRTC interoperability test.

The opt-in `AppSharingMediaSmokeTest` also passed locally on September 28, 2026
with JxBrowser 9.5.2 / Chromium 154.0.8037.58. Two private loopback WebRTC peers
decoded synthetic red/green canvas pixels through the production VP8 encryption
and ScriptTransform receiver path. A second real encoded-frame pass verified
host signatures and rejected altered and replayed frames before decoding the
same pixel probes. This test uses an isolated browser profile and no SFU,
external network, user window capture, or input injection. It does not establish
real-network performance or SFU compatibility.

To run it explicitly with already installed matching Chromium and the existing
`local.properties` JxBrowser license:

```sh
BOSS_TEST_APP_MEDIA=1 BOSS_TEST_APP_MEDIA_CHROMIUM_DIR=/path/to/matching/chromium \
  ./gradlew :composeApp:desktopTest --tests '*AppSharingMediaSmokeTest'
```

`AppSharingSfuSmokeTest` is a separate opt-in real-provider harness. Configure
the debug/local Edge function with SFU credentials server-side, and supply a
dedicated test account in an owner-only JSON file containing `endpoint`,
`userId`, `accessToken`, `anonKey`, and `viewerBaseUrl` (HTTPS). The account needs
the default auto-admission/control preferences; the harness does not change
them. Account/provider secrets never enter browser assets or test reports.

```sh
BOSS_TEST_APP_SFU=1 BOSS_TEST_APP_SFU_CREDENTIALS=/private/path/test-account.json \
  BOSS_TEST_APP_MEDIA_CHROMIUM_DIR=/path/to/matching/chromium \
  ./gradlew :composeApp:desktopTest --tests '*AppSharingSfuSmokeTest'
```

This harness stages 1/3/10 independent viewers of one publication in one fresh
private browser process. It requires decoded synthetic pixels and continued
frame progress, measures publisher upload/encode time and aggregate viewer
receive/decode time, exercises persistent encrypted control and replay/tamper
rejection, then checks disconnect isolation and remote-generation revocation.
Its report contains only synthetic counts/timings. It is not a cross-device or
native capture test, and its aggregate process topology cannot establish
production host CPU/RSS budgets. The harness being present does not mean the
real-provider run has passed; retain its actual report as rollout evidence.

Before production rollout, verify other browser versions and the legacy
encoded-transform API, Cloudflare SFU credentials and connectivity,
NAT/TURN behavior, native capture permission and fidelity, and real control
delivery. Ed25519 WebCrypto plus encoded media transforms are required; older
browsers are refused. Validate text readability, 1/3/10-viewer load and revocation
with real media. The exact-window native capture implementation currently has a
macOS 14+ capability boundary. Explicit multiple windows, owned Compose dialogs,
and demand-gated screenshots are implemented. Idle negotiated publications retain
their cipher counters; no new canvas frames are requested without viewers.
Windows/Linux capture, native menus/system sheets, IME, automatic quality,
clipboard/audio and real-device fidelity remain separate delivery gates.
This custom versioned framing is experimental,
not a claim of SFrame interoperability or an audited production protocol.
