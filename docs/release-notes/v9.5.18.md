# BOSS v9.5.18

**Release Date:** 2026-09-15

Two changes, both about state that outlived the thing it described. Clipboard actions from a
browser context menu now target the exact frame that was right-clicked, carried as an opaque
per-menu token rather than inferred from keyboard focus; and the screen-capture picker's pending
requests have the same cardinality as the picker itself, so a superseded request is cancelled
instead of being left alive forever. Global Search also matches an open tab by its URL or file
path, not only by title.

## Highlights

- **A clipboard action from a context menu targets the frame that was clicked.** Chromium hands
  the exact `Frame` to the context-menu callback and the browser tab's menu discarded it, falling
  back to `browser.focusedFrame()` - but keyboard focus does not always move when a right-click
  happens, so Cut, Copy and Paste inside an iframe (an OAuth or payment form, typically) could
  occasionally act on the main frame instead. `BrowserMenuContext` is a new opaque token in
  `plugin-api-browser`: the host mints a fresh one per right-click, embeds it in
  `BrowserContextMenuInfo`, and a plugin forwards it to `copySelection`/`paste`/`cut`/`selectAll`
  (#693)
- **The routing carries no shared state, which is what the first attempt got wrong.** A
  `@Volatile` `contextMenuTargetFrame` held between the callback that wrote it and the command
  that read it meant dismissing a menu left a stale frame behind for ordinary, later clipboard
  operations to use. Tokens are per-invocation and per-handle instead, and revoked by navigation
  (including same-document transitions), browser close and callback replacement. A token whose
  frame has been collected or whose generation is stale is a **safe refusal**, never a fallback to
  some other frame - and with no token supplied, resolution is the unchanged
  `focusedFrame()`-then-`mainFrame()` (#693)
- **A superseded screen-capture request is cancelled, not abandoned.** `ScreenCaptureNotifier`
  kept pending requests in a `ConcurrentHashMap` while the picker has exactly one visible slot, so
  a second request overwrote what was on screen and left the first caller's
  `StartCaptureSessionCallback` waiting on an answer nobody could give. `SingleCaptureRequestSlot`
  gives the native callback storage the picker's own cardinality: `publish` returns whatever it
  replaced so the caller can cancel it, and `take` refuses a stale UI action without disturbing
  the request currently on screen (#509)
- **Global Search finds a tab by its URL or its path.** `searchTabs` matched titles only, and
  `TabResult` hardcoded `url = null` / `filePath = null` on every hit - so a browser tab whose
  title never mentions its domain, or an editor tab someone wants to find by path rather than
  filename, could not be found at all (#606, #648)

## Features

- **Tab search by URL and file path**: a browser tab's `FluckTabInfo.currentUrl` and an editor
  tab's `EditorTabInfo.filePath` are now scored, through the same substring-containment gate
  (`proseScore`) that `searchRecentPages` already applies to a page's URL - a fuzzy subsequence
  match over a whole URL or path is close to meaningless. The best of title, URL and path wins, and
  highlight ranges stay on the title only, since a URL-only hit has nothing in the title to
  underline. A tab of neither type (terminal, diff) still matches on title alone with both fields
  left null. The tab row's subtitle now leads with the Space name - disambiguating identical URLs
  open in different Spaces or windows - followed by the URL, path or tab type, in place of the old
  `tabType • workspaceName` line. 11 tests cover URL-only and path-only matches, the fields being
  populated for the right tab type, a short query not matching a URL by fuzzy accident, title and
  URL both matching taking the higher score with title ranges preserved, and live navigation
  changing which URL matches (#606, #648)
- **`BrowserMenuContext` on the browser plugin API**, backward compatible throughout: the
  interface is new and opaque, `BrowserContextMenuInfo.menuContext` is nullable, and the four
  editor commands take it as an optional argument, so a plugin built against an older API is
  unaffected and gets today's focus-based resolution (#693)

## Bug Fixes

- **A dismissed context menu can no longer corrupt a later clipboard operation.** This was the
  reported regression from the first version of the frame routing, and it is closed by removing
  the shared mutable state rather than by clearing it more carefully. Seven regression tests cover
  explicit targeting, dismissed-menu isolation, two-menu independence, context beating focus,
  closed-frame safety, API propagation and statelessness (#693)
- **The capture picker resets its selection for a new request.** `selectedTab`, `selectedSource`
  and `includeAudio` were `remember { }` with no key, so a request that replaced the one on screen
  inherited the previous request's tab and highlighted source. They are keyed on `requestId` now,
  and the picker takes a `requestId` parameter for it (#509)
- **A replaced capture request is logged and its callback cancelled** - a closed native peer
  throwing on `cancel()` is caught, so it cannot stop the new caller arming its own timeout (#509)
- **Every `ActiveTabsService` RPC requires a verified caller.** All seven were reachable by any
  process that could open a connection to the kernel IPC server, not only the plugins the host
  loaded: `watchActiveTabs` disclosed every open tab's title and URL across every window with no
  credential at all, `createBrowserTab` could force navigation to an arbitrary URL, and
  `selectTab`/`closeTab` could manipulate what the user is looking at. Unary RPCs call
  `authenticatedCallerOrRefuse`, and the stream captures
  `ProcessIdentityInterceptor.CURRENT_IDENTITY` synchronously in the method body - before the flow
  is collected, on the thread the interceptor's context is current on - then re-checks it before
  every emission, so a revoked caller's stream is refused before an already-held handle receives a
  value it should no longer see. The three mutating RPCs record an attributed audit line carrying
  the caller and RPC name only, never URLs or titles (#646)

## Improvements

- **The frame-choice KDoc now describes what the code does.** It had carried a long note on why
  `focusedFrame()` was used despite `PopupWindowContextMenu` reaching the opposite conclusion, and
  named preferring the callback's own frame as "the durable answer ... not done here". That is what
  this release does, so the note is replaced by the two-branch rule it became (#693)

## Dependencies

- `boss-plugin-api` 1.0.90 -> 1.0.93, which is where the released `BrowserMenuContext` shape the
  host reconciles against lives (#693)
- `essenty` 2.5.0 -> 2.6.0 (#655). `plugin-api-core` now declares `essenty-back-handler` and
  `essenty-instance-keeper` as `api` dependencies, keeping Decompose's transitive Essenty modules
  on the host's selected version rather than letting them resolve independently
- `org.graalvm.buildtools.native` 1.1.11 -> 1.1.12 (#656)

## Known Limitations

- **Exact-frame routing is opt-in for plugins.** The host mints a token for every right-click, but
  a command only targets that frame if the plugin forwards the `menuContext` it was given; a
  plugin that ignores the field keeps the previous focus-based behaviour
- **A revoked token refuses rather than degrades.** If the menu's frame has navigated or been
  collected between the right-click and the command, the action does nothing and logs it - there
  is deliberately no fallback to another frame, since acting on the wrong frame is the defect this
  closes
- **The capture picker keeps the newest request**, matching its existing visible-state policy. The
  earlier permission rationale takes the opposite approach and refuses newcomers, but it runs
  before any capture picker is requested
- **Twelve kernel IPC service bridges remain unauthenticated.** #646 closes the active-tabs bridge
  on top of the Supabase proxy and Download bridges from #550 and the secrets and RBAC bridges
  from #505. The rest still trust every local caller
