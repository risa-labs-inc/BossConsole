# BOSS v9.5.21

**Release Date:** 2026-09-18

One integration batch (#876) across 148 files. Two themes run through it: state that was being
written without coordination now serializes and writes atomically - recent files, user data and run
configurations - and a run of path bugs that only ever showed on Windows are closed at the source
rather than per call site. Alongside those, MCP gains workspace and terminal lifecycle tools so an
agent can bootstrap from a cold start, the mutating gate now weighs a provider's own `readOnly`
declaration, and five server-side fixes stop the edge functions and two database tables telling an
anonymous caller more than they should.

## Highlights

- **MCP can open a workspace and a terminal from a cold start** (#794, resolves #780).
  `list_workspaces`, `open_workspace`, `create_workspace`, `open_terminal` and `close_workspace`
  (plus `workspace_*` / `terminal_*` aliases) let an agent bootstrap with zero open windows.
  Caller-supplied paths and commands go through `CLISecurityValidator`, the same policy the CLI and
  deep links use; `open_terminal` returns the authoritative mounted tab and terminal id rather than
  a predicted one; `list_workspaces` is a pure read and creates no window. All of them declare
  `readOnly = false`, so the ASK default is their confirmation layer - the role the `DeepLinkOrigin`
  prompt plays for `boss://terminal?command=`
- **The mutating gate weighs the provider's own declaration** (#808, refs #804). It is a fail-closed
  OR: the host's name signals are final, and `McpToolDefinition.readOnly` is consulted only after
  them, so `readOnly = false` makes an innocently named tool mutating while `readOnly = true` can
  never launder a name the host already knows. `null` preserves the name-only answer bit for bit.
  Since `readOnly` defaults to `true` in the plugin API, this catches an honest plugin declaring
  side effects and is deliberately not a defence against a hostile one that lies
- **Recent files and user data are serialized and written atomically** (#795, fixes #764, #762).
  Both read-modify-wrote their JSON from `Dispatchers.IO` with no coordination and persisted with
  `writeText`, which truncates before streaming. A mutex now serializes mutation, both use
  `atomicWriteText`, and `loadAsync` merges rather than assigns - so a file opened during startup is
  no longer dropped from the recorded list. `UserDataStorage` holds its lock across
  save/clear/`setPluginWizardCompleted`, which is what made the plugin wizard flag revert to false
  and re-run the wizard; an undecodable `user_data.json` now falls back to the pending marker
  instead of dropping the flag
- **A pasted magic link signs in** (#740, #789). "Paste magic link manually" rebuilt the verify link
  only when the pasted text contained a literal `token=`, but the sign-in email wraps the
  confirmation URL in the redirect function's `url=` parameter, often percent-encoded - so the paste
  was treated as a web address, dropped as unrouted, and the screen showed nothing. Reproduced on
  9.5.17 with a real email. `signInDeepLinkFor` now decodes the query and reads `token` or
  `token_hash` from the link or its `url=` value, matching `supabase/functions/redirect/app.ts`, and
  tolerates a link a mail client wrapped across lines or appended a fragment to. Text that is not a
  sign-in link reports an error rather than nothing
- **The GitHub fallback update download is verified** (#798, refs #797). The fallback passed
  `sha256 = null`, so the one download path that runs precisely because a CDN is already misbehaving
  staged its installer with no integrity check - and a staged installer later runs elevated. Both
  paths now pass the catalog hash through one extracted `verifyDownloadedAsset` gate, and a mismatch
  is discarded rather than staged

## Features

- **Browser zoom badge in the window top bar** (#793). It keys on the active browser handle, so a
  tab switch within a window updates it, and its zoom listener is removed on change and on dispose
  rather than accumulating. Custom zoom level and favicon cache key now survive a tab copy and a
  split-view move (#777)
- **Workspace and terminal MCP tools** (#794): `WorkspaceMcpToolProvider`, with cold-start window
  creation, a bounded wait for `SplitViewStateRegistry` registration, `create_workspace` decoupled
  from window activation so it only persists configuration, and deterministic window targeting - an
  omitted `windowId` is refused while several windows are open, and an unknown one lists the open
  ids so an agent can correct itself
- **Persistent Home navigation in the active pane** (#757), reachable from the File menu as well,
  with a subtle selection treatment rather than a filled row. With the browser tool absent it says
  so instead of doing nothing
- **Plugin toasts get a copy button** (#745) and the stack gets a "Clear all" control (#743)

## Bug Fixes

### Browser

- **Save as PDF confirms an extension-appended overwrite** (#746). A native save panel protects the
  path in its name field, so appending a required `.pdf` after the panel closes could point at a
  different existing file the panel never asked permission to replace. That one case now re-presents
  the real target as the next suggestion, where the panel performs its own overwrite confirmation;
  cancelling refuses the save. macOS only - Windows and Linux retain the JxBrowser defaults
- **The form field detector is executed, not just read** (#609). It is JavaScript inside a Kotlin
  string injected into every frame of every page, and was the only one of those with no test at all.
  `scripts/test/test-form-field-detector.js` runs both of its scripts against a fake DOM and
  compares its nine emitted keys against the host's hand-written extraction regexes, so a rename on
  either side fails loudly instead of silently yielding an empty string forever

### Windows paths

- **The editor breadcrumb splits on path segments** (#753). The bottom bar appended `/` to the
  project path and split on `/` alone, which does not divide a native `C:\Users\dev\repo`
- **Spotlight file-name highlights shift by the platform separator** (#716). `searchFiles` rebased
  match ranges onto the file name using `lastIndexOf('/')`, but `relativePath` is backslash-joined on
  Windows - so `uiButton` against `app\ui\Button.kt` underlined "on" and "kt" rather than "Button",
  and a match past the name's length underlined nothing
- **Run-configuration disambiguation works** (#653). `makeNamesUnique` split a stored native
  `filePath` on a literal `/`, so two configurations with the same name in different directories
  stayed byte-identical in the Run dropdown. The project name now comes from `extractFileName()`,
  which also closes a latent path leak into the label

### Run configurations

- **Concurrent configuration updates are preserved** (#755, #791, refs #754), with a regression suite
  for the mutex
- **Loaded settings survive a failed startup cleanup** (#788), and a malformed settings file still
  propagates to the startup error handler

### Plugins

- **A plugin's search provider reaches global search** (#670). Neither `TrackingPluginContext` nor
  `SandboxedPluginContext` forwarded `registerSearchProvider`, so no plugin's provider ever arrived -
  the second instance of the three-wrapper gap this repo already records for `brokeredCredentialProvider`.
  `PluginContextWrapperForwardingTest` now expects every `PluginContext` member, inherited ones
  included
- **Removing a plugin completes across every open window** (#783). Uninstall now unloads in each
  active manager that reports it installed, cleans up every recorded jar path, fails if any window
  still reports it installed, and restarts dependents across windows
- **Overlapping host plugin updates are rejected** (#612) rather than interleaving
- **Plugin process memory and threads are read per platform** (#785, #801). A `ps` run for the
  Performance panel waited with no timeout on `Dispatchers.Main` and every failure was swallowed, so
  a JNA load failure on Windows showed 0 bytes and 0 threads with nothing logged. Runs are now
  bounded at 5s with the child killed and reaped on every failure path, and a failing source is
  reported once and again when it recovers
- **Toast text is bounded** (#742, refs #154) so a verbose stack cannot strand the dismiss button
- **11 unused `PanelIds` constants are gone** (#720, fixes #719), including four whose id strings no
  plugin registers

### Search

- **An in-flight search is cancelled when the query is cleared** (#718, fixes #717), and an obsolete
  Spotlight publication can no longer overwrite a newer one

### Tabs

- **A tab tooltip stays visible while its title updates** (#752)

### Remote UI

- **Property removals survive a diff** (#763). `WidgetDiffEngine` must distinguish three operations
  on a widget property, and an empty string cannot mean removal - it is a valid value for text,
  labels, selections and event ids. `NodeUpdated` now carries `removedProperties` beside
  `changedProperties`, mirrored on the wire by an additive field 4 in IPC 1.2.0

### CLI

- **Force delete no longer follows symlinks** (#778), and the plugin templates get slf4j so a
  scaffolded plugin logs through the structured path from the first build

### Server-side security

- **`plugin_ratings` is restricted to the server-side rating pipeline** (#761). Its four RLS policies
  carried no `TO` clause, so `SELECT USING (true)` let any holder of the shipped anon key read every
  rating row across all users, and the write policies bound only `user_id` - making the FK violation
  an existence oracle for org-scoped plugins. Mirrors the `plugin_downloads` migration; the desktop
  client never touched this table directly, so nothing changes for the shipped app
- **The edge functions stop returning raw exception text** (#771). All three deployed functions run
  with `verify_jwt=false`, and 32 sites returned `{ error: <exception>.message }` with a 500 to an
  anonymous caller - PostgREST schema-cache details, internal hosts, parser internals. Every route
  catch and all three global `onError` handlers now log server-side and return a fixed
  `Internal server error`
- **Crash-report repo resolution is bound to one GitHub owner** (#775, refs #774).
  `plugins.homepage_url` is publisher-controlled and crash-report files issues with the server's
  `GITHUB_TOKEN`, so a publisher could aim it at any repository. A row or homepage resolving outside
  `risa-labs-inc` (overridable via `CRASH_REPORT_ALLOWED_REPO_OWNER`) now falls back to
  `DEFAULT_REPO`
- **The last three SECURITY DEFINER functions have a closed `search_path`** (#790)

## Improvements

- **IPC 1.2.0** adds `NodeUpdated.removed_properties` as field 4. Older receivers safely ignore it
  and retain a stale property until a full tree arrives, which is the existing failure rather than a
  new one. `NodeUpdated` became a manually implemented plain class to keep its three-argument
  constructor, `component1`-`component3`, `copy` and generated `copy$default` JVM descriptors intact
  for already-built runtimes
- **The MCP policy dialog's section buckets and the invoke gate share one `isMutating` call**, so
  they cannot disagree about which tools View may select
- **CI**: the SwipeNav parity timeout is raised to 120s and orphaned node processes are killed on the
  Windows runner (#787); crash-report checks are gated on dev
- **Docs**: `RELEASE_REBUILD_GUIDE.md` warns that re-running an existing tag with different bytes
  leaves GitHub on the old asset and Supabase on the new hash, which the fallback verification above
  now fails closed on. The README lists third-party community plugins in a separate, explicitly
  unaudited section (#779)

## Known Limitations

- **An operator "Always Allow" on `open_terminal` runs later invocations unconfirmed**, i.e. as
  strong as an unconfirmed external deep link. The command still passes the shape check and the shell
  risk evaluation (HIGH, CRITICAL for destructive patterns) on every call
- **The provider `readOnly` signal is not a defence against a hostile plugin.** It defaults to `true`
  in the plugin API, so it catches an honest plugin declaring side effects; a plugin that lies is
  caught only by the host's name signals, which is why those stay final
- **The locking and atomic-write behaviour in the recent-files and user-data fix has no automated
  coverage** beyond the pure merge and load-decision tests and was verified by hand; the
  clear-during-load window is documented as a known limitation in the code
- **`registerSearchProvider` forwarding does not yet deliver anything.** `DefaultPlugin` does not
  implement it, so every plugin still gets null - the wrappers only stop a future host implementation
  being swallowed. `PluginContextWrapperForwardingTest` matches by name, so it cannot tell a wrong
  forward from a right one, and a third wrapper has to be added to it by hand
- **The PDF overwrite confirmation is macOS only.** Windows and Linux keep the JxBrowser defaults
- **The Windows path fixes are asserted on every runner by injecting the separator**, because a
  Windows-shaped path proves nothing on a POSIX host. The end-to-end Spotlight case uses the host
  separator and is red only on Windows
