# BOSS v9.5.36

**Release Date:** 2026-10-04

BOSS can now update itself: new releases download in the background and install after you quit
(#1807). Window sharing streams the whole window continuously at up to 60 FPS, viewers can take
scoped remote control, and Windows and Linux X11 get native capture helpers (#1810).

## Highlights

- **Automatic app updates** (#1807). Turn on Automatic Updates in Settings and BOSS downloads new
  releases in the background, then installs them after you quit. BOSS never quits or relaunches
  itself. The next launch of the new version shows a one-time "BOSS updated" toast
- **Continuous window sharing** (#1810). A shared window is streamed as live video instead of
  periodic snapshots. It starts at 30 FPS and moves up to 60 FPS when the machine keeps up, with
  sharper text at up to 1920 pixels on the long edge
- **Remote control in shared windows** (#1810). Viewers allowed to control a window request control
  when they connect, and can type into web pages, the native address field and toolbar menus
  without bringing the window to the front
- **Windows and Linux capture helpers** (#1810). Native helpers capture the exact BOSS window on
  Windows 10 2004 and later and on Linux X11 (including XWayland), behind real OS and session checks

## Features

- **updater**: new Automatic Updates switch in Settings. Release builds turn it on by default and
  Gradle development runs turn it off; an explicit choice is saved. Update banners and prompts stay
  hidden in automatic mode, while progress and errors remain in Settings, which shows "Update ready"
  once a download is waiting for you to quit (#1807)
- **updater**: the installer helper refuses to install automatically from a Gradle development
  process, and each install uses its own uniquely named helper files (#1807)
- **sharing**: each shared window and its owned dialogs are captured with a continuous native
  stream and sent over the existing encrypted VP8 connection. Pixels go straight to the encoder with
  no PNG encoding, and frame rate drops back to 30 FPS under CPU or encoder pressure (#1810)
- **sharing**: popups and transparent overlays are composed with their real alpha, and each
  surface is sized in logical units so mixed display density does not double a popup (#1810)
- **sharing**: browser and native viewers show a performance footer with frame rate, bitrate,
  relay round trip and a Good / Fair / Poor connection rating for both the viewer and the host
  (#1810)
- **sharing**: control-capable viewers request control on connect, never displace a viewer who
  already has it, and release it on blur, when the page is hidden, or on disconnect. View-only
  roles never request control (#1810)
- **sharing**: on macOS the native title bar stays visible while sharing, and remote clicks on
  toolbar items, the address field, toolbar menus and address suggestions reach the right
  window. Remote input can never open application menus or start or widen a share (#1810)
- **sharing**: sharing can also be started from the title-bar Sharing menu, which merges with the
  terminal's own sharing button. Those entries stay local-only and are disabled for remote viewers
  (#1810)
- **mcp**: the terminal's MCP title-bar button now also carries the activity log and the MCP
  access controls, shown as "MCP: YOLO" while YOLO mode is on (#1810)

## Bug Fixes

- **browser**: keyboard focus is now exclusive between the native URL field and the web page, and
  the page gets its keyboard back after you finish editing the address on macOS (#1810)
- **browser**: Option+Shift+Left/Right in the macOS address field selects by word, including from a
  remote viewer (#1811)
- **sharing**: stopping a share no longer interrupts its own cleanup, so the final black frame and
  the stop callback always run before the streams close (#1811)
- **release**: the Windows and Linux capture helper build works again when Gradle restores it from
  the configuration cache, which broke packaging (#1811)

## Improvements

- **ci**: every PR build now builds the capture helper twice, through a configuration cache store
  and restore, so a packaging-only failure is caught before release (#1811)
