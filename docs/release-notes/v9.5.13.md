# BOSS v9.5.13

**Release Date:** 2026-09-10

One validation batch off `dev` (#491), and the theme is code that answered the wrong question.
A credentials surface offered secrets for sites that merely shared a word with them; Run Main
resolved a language name against a table of file extensions and printed `echo 'Unknown language'`
for every language but two; a forwarded `boss://plugin?…&action=…` link reported success whether
or not any handler existed to run it; and a sensitive URL parameter whose value contained a colon
had the tail of that value survive log redaction verbatim. No dependency moved.

## Highlights

- **A secret is suggested only for its own domain, or a real subdomain of it.**
  `WebsiteMatchingUtil.calculateMatchScore` had four tiers, and the bottom two did not establish a
  domain relationship at all: a `contains` tier scored 0.7, so `snapple.com` matched `apple.com`
  and every `.com` secret matched every `.com` site, and a shared-token tier scored 0.5 on any
  label two domains had in common, so `apple.com` matched `apple.org` and `login-apple.com`
  matched `apple.com`. Both are gone rather than narrowed - excluding bare TLD labels from the
  token check closed the "every `.com` matches every `.com`" case and left two unrelated
  registrable domains matching on a brand-ish word, which is the same wrong-site-credential
  problem one door along, and no shared-word heuristic closes it for good. What remains is
  equality (1.0) and a dot-delimited suffix on either side (0.9), which is what a password manager
  keys on; a credentials surface takes precision over recall. Two blank sides now score 0.0
  explicitly, because an unresolved domain and a secret with no recorded website would otherwise
  satisfy the exact-match test vacuously as `"" == ""`. `WebsiteMatchingUtil` had no test coverage
  at all before this (#461, closing #460)
- **Run Main works for languages other than Java and Go.**
  `EditorContentProviderImpl.executeMainFunction` resolved the language with
  `Language.fromExtension(mainFunction.language)`, but `MainFunctionInfo.language` is serialised by
  `toMainFunctionInfo` as `language.name.lowercase()` - a language *name* (`kotlin`, `python`),
  where `fromExtension` matches *extensions* (`kt`, `py`). Every language whose enum name is not
  also its extension resolved to `Language.UNKNOWN`, and `generateCommand` maps `UNKNOWN` to the
  literal command `echo 'Unknown language'`; `java` and `go` worked by coincidence, their name and
  extension being the same string. The language now comes from `mainFunction.filePath` through a
  testable `runLanguageForMainFunction` helper, which is where `detectMainFunctions` derived it in
  the first place, so it round-trips (#459, closing #458)
- **A forwarded plugin action link reports whether it actually ran.**
  `boss://plugin?id=<x>&action=<y>` dispatched into `DeepLinkActionRegistryImpl` fire-and-forget
  and discarded the boolean verdict, so `SingleInstanceManager` answered `RESPONSE_OK` even when
  no handler was registered for that id, or the handler declined, or it threw - a caller scripting
  BOSS over `boss://` links (a CLI, another instance, an agent) could not tell a real success from
  a silent no-op. `processDeepLink` now returns a `Deferred<Boolean>?`, non-null for exactly that
  one route and null for every other, which keeps today's behaviour everywhere else and lets the
  OS-delivered and CLI callers ignore the value unchanged. The channel awaits it for five seconds -
  well under `CONNECTION_TIMEOUT_MS`, so the socket's own budget can still close a wedged
  connection rather than race this wait - and distinguishes three answers: handled, not handled,
  and unknown at the deadline. **An action is never replayed automatically**, even after a lost
  reply: a handler can have side effects whatever its verdict, so `forwardDeepLinkWithRetry` gives
  an action link one attempt while auth and other open requests keep their three (#470)
- **A colon inside a sensitive URL parameter no longer leaks a fragment of the token.**
  `filePathPattern`'s `[^\s:]+` stops at the first colon, correctly, because a colon there usually
  marks a `host:port` boundary worth preserving - but a *value* containing one was then only
  partly consumed and the tail survived the later replace verbatim, so
  `[url=https://…?token=abc:def]` sanitized to `[url=https:[PATH]:def]`. Measured, not
  hypothetical. A new pre-pass redacts sensitive-named query and fragment parameters before the
  path pass can see them, so nothing containing a colon is left by the time it runs - the fix is in
  what reaches that pass, not in loosening a boundary that exists for the `host:port` case. It
  fires on `?`, `&` and `#`, consumes adjacent wrapper punctuation (a `)` or an apostrophe is legal
  inside a URI value, and treating one as a log wrapper leaves the colon and the suffix exposed),
  keeps `null`/`true`/`false` readable, and leaves free-text diagnostics like `exit_code=1` and
  `status_code=500` alone. `maskUriParams` and the new pass now share one
  `sensitiveUriParamNames` set instead of holding separate copies (#471, refs #109)

## Bug Fixes

- **secrets**: the credential-suggestion scorer no longer matches unrelated sites; `getDisplayName`
  also stopped duplicating a word for a digit-initial domain, where
  `replaceFirstChar { c -> … else it }` returned the whole enclosing word rather than the
  character (`1password.com` rendered as "1passwordpassword", `9gag.com` as "9gaggag")
  (#461, closing #460, tests retained from #467)
- **editor**: Run Main resolves its language from the file path rather than the stored language
  name (#459, closing #458)
- **deep-link**: a forwarded plugin action link reports its handler's real verdict, and is never
  retried automatically (#470)
- **deep-link**: Linux's expected `APP_OPEN_URI` gap is no longer logged as an error.
  `setupDefaultHandler` caught `Desktop.setOpenURIHandler`'s `UnsupportedOperationException` in the
  generic `Exception` branch and logged it at ERROR with a full stack trace on every Linux launch.
  The JDK's X11 Desktop peer supports no `APP_OPEN_URI` action - a documented outcome, and delivery
  already works through `processCommandLineArgs` reading `argv`, both at cold start and forwarded
  to a running instance - so it now logs at DEBUG, catching the specific exception before the
  generic branch exactly as `setupOpenFileHandler` already does for the equivalent
  `APP_OPEN_FILE` gap (#437, closing #410)
- **logging**: a sensitive URL parameter whose value contains a colon is redacted whole
  (#471, refs #109)

## Improvements

- **deep-link**: the startup forwarding retry loop moves out of `main.kt` into
  `DeepLinkForwarding.kt` as `forwardDeepLinkWithRetry`, alongside `awaitPluginAction`, so the
  "how many attempts does this link get" decision and the "what does an unknown verdict mean"
  decision sit next to each other and are unit-testable. Cancellation of the waiter itself still
  propagates to its caller; a cancelled dispatch is a negative verdict
- **docs**: `AGENTS.md` records the plugin-action acknowledgement contract on the single-instance
  channel - what reports failure, the five-second wait, that panel-open links still only
  acknowledge queuing, and that startup never retries an action. `docs/SECRET_BROWSER_INTEGRATION.md`
  drops its "fuzzy matching" description for the scoring the code now does, and states plainly that
  the guide documents the host utility while current Fluck matching lives in the separate
  `boss-plugin-fluck-browser` repository

## Known Limitations

- **The strict scorer is not a registrable-domain policy.** `calculateMatchScore` rejects
  substrings and shared labels, but it does not validate public suffixes - `extractMainDomain`
  keeps its existing handling of six hardcoded two-part suffixes rather than consulting a
  public-suffix list, so unrelated domains under an unlisted public or private suffix can still
  collapse onto one another before the scorer sees them. These scores establish neither complete
  registrable-domain nor hosted-tenant isolation (#461)
- **An action's outcome can be genuinely unknown, and that is reported rather than guessed.** The
  five-second deadline cancels a dispatch still queued, but an already-running synchronous handler
  cannot be interrupted, so its outcome is unknown at the deadline and the channel says so instead
  of choosing OK or ERROR. A `true` verdict also means the handler reported the action handled, not
  that asynchronous work it started has finished (#470)
- **Panel-open links still only acknowledge queuing.** `boss://plugin?id=…` with no `action`
  returns null from `processDeepLink` and keeps its fire-and-forget behaviour, as does every other
  host on the scheme; `RESPONSE_OK` for those means "queued", exactly as before. The wire verdict
  changes nothing for OS or CLI callers that ignore the return value (#470)
- **The redaction pre-pass is a text matcher, not a URI parser.** It reads `?`, `&` and `#`
  separators and does not interpret legacy semicolon separators or percent-encoded parameter
  *names*. A non-sensitive parameter's colon is out of scope and still meets `filePathPattern`'s
  pre-existing boundary unchanged (#471)
