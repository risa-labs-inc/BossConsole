# BOSS v9.5.11

**Release Date:** 2026-09-09

A second validation batch (#430) promoting the rest of the reviewed `dev` work to `main` - 245 files,
and the largest release since 9.5.0. It adds a headless CLI agent harness (`boss status`, `boss mcp`),
a governed approval gate and audit ledger for every MCP tool invocation, a chrome density setting that
was built and unreachable, and a What's New feed on the dashboard. The corrective half is dominated by
the keyboard: two key-name vocabularies had drifted far enough that `Ctrl+Tab` fired in none of the four
shipped presets, and every rebind made in the Shortcuts screen was stored as a number no matcher
compares against. gRPC and protobuf both move.

## Highlights

- **A headless CLI agent harness.** `boss status --json`, `boss mcp list`, `boss mcp describe` and
  `boss mcp invoke` reach a running BOSS over the authenticated single-instance loopback IPC, with a
  single-line Base64 wire protocol and a fast path that executes before GUI bootstrap. Denials from
  the host's MCP policy are preserved rather than flattened into a generic failure, and headless
  diagnostics are isolated so a plugin's broken schema cannot take the listing down. Documented in
  `docs/CLI.md` (#349)
- **Every MCP tool call now passes a policy, and every outcome is journaled.** `McpPolicyEngine` is
  fail-closed on a damaged configuration, unknown tool names default to ALLOW, and known mutations
  default to ASK behind a 45-second prompt delivered to exactly one window. `McpOperationLedger`
  rotates at 10 MB x 5. Argument redaction moved off `LogSanitizer.sanitizeMap`, which masked any
  string 20 characters or longer - that hid the file paths, URLs and shell commands an operator reads
  to decide whether to approve, so `McpArgumentSanitizer` masks on a sensitive key name or an
  unambiguous credential shape (JWT, GitHub token, `sk_`/`pk_` vendor key) instead. The risk
  classification from #336 feeds this same path, so there is no second prompt (#371, #336)
- **`Ctrl+Tab` and `Ctrl+Shift+Tab` were dead in all four presets, and rebinds were stored as
  numbers.** `AWTKeyboardInterceptor.getKeyName` and Compose's `Key.toString()` are two vocabularies
  over one keyboard, and they had drifted on fourteen keys - nine of them reachable in a running app,
  because `Key.toString()` falls through to AWT's `getKeyText` and answers with the macOS glyph once
  the toolkit is up. Separately, the Shortcuts screen persisted `key.keyCode.toString()`, a packed
  number no matcher compares against, so a rebind fired on neither path. Names are folded through
  `canonicalKeyName` before storage, existing keymaps are repaired on load *and* migrated on disk, and
  `KeyVocabularyAgreementTest` walks both tables over all 73 bindable keys so the next divergence
  fails a build rather than a keystroke (#335, #376, closing #329 and #375)
- **Hot-reloading the browser plugin no longer empties every tab.** Force-unloading
  `fluck-browser`'s classloader does not un-bind the JxBrowser native views it created, so every open
  tab - and every tab opened afterwards, the factory having gone with it - drew an empty box, and a
  second reload did not recover it. `HotReloadPolicy` names the plugins that must never be swapped in
  place; their new jar is staged into `installed.json` and applied by the next cold start, with a
  status message saying so (#352, closing #71)

## Features

- **ui**: a **Density** control in `Settings > Bars` (Compact / Comfortable / Spacious), indexed in
  Settings search. `ChromeDensity`, `ChromeDimens.of()` and `LocalChromeDimens` already existed and
  every bar already read its height from them, but nothing ever *provided* `LocalChromeDimens`, so it
  resolved to its `staticCompositionLocalOf` default forever - the scale was built and unreachable.
  A fresh install below 1000dp logical screen height defaults to Compact, decided by a pure
  `defaultDensityFor(screenHeightDp)` so it is testable without a display, with the `Toolkit`
  read wrapped so a headless start cannot break a first run. Existing settings files decode to
  exactly the chrome they already had, so no settings-version bump was needed (#305, addressing #239)
- **files**: opening an `.html` file asks whether to open it as a file or as a webpage, with the
  answer persistable. The prompt is routed through its own `HtmlFileOpenQueue` rather than the general
  dialog host, honours a navigation intent that already names the destination, and releases pending
  prompts on failure so a routing error cannot strand the open (#333)
- **cli**: `boss status` and `boss mcp` (list / describe / invoke), over the authenticated
  single-instance channel. `scripts/boss`, `boss.bat` and `boss.ps1` carry the new subcommands and
  `scripts/test/test-headless-cli.sh` exercises them (#349)
- **mcp**: `McpApprovalBus`, `McpApprovalDialog`, `McpPolicy`/`McpPolicyEngine` and
  `McpOperationLedger`, wired through `McpToolRegistryImpl.invoke` and surfaced in the bottom bar
  (including **Revoke MCP session trust**). Queue overflow and cancellation before or after dispatch
  record distinct ledger dispositions, and window teardown denies the request that window owned
  (#371)
- **mcp**: `DefaultMcpRiskEvaluator` classifies a call from its tool name and parsed arguments -
  deterministic and rule-based, no LLM, no logging of the arguments it reads. Shell tools are
  evaluated on the command, `secret_get` is CRITICAL. HIGH and CRITICAL names take the mutating
  default; the reasons and the sanitized arguments render in the existing approval dialog (#336)
- **dashboard**: a read-only **What's New** release feed on the home screen, sharing the updater's
  release fetch rather than opening a second one. Refresh bursts are coalesced, realtime refreshes
  survive a shared fetch, visible history is preserved across one, and `isUnseenRelease` /
  `advanceLastSeenReleaseVersion` compare parsed versions so a downgrade cannot rewind the marker
  (#381)
- **remote-ui**: out-of-process UI surfaces authenticate their process identity
  (`ProcessTokenRegistry`, `ProcessIdentityInterceptor`, `ProcessTokenClientInterceptor`) and are then
  placed by `RemoteUiPlacement`, with the ownership and placement lifecycle races closed and the
  recovery cases exposed to JUnit. `RemotePanelComponent` and `RemoteTabComponent` collapse onto a
  shared `RemoteSurfaceComponent` (#348)
- **search**: selecting an `mcp__boss__*` row in double-shift search now reveals the Toolbox, where
  the kill-switches are. Agent-less operators could find the tools and then had nothing to press;
  a selection made when the Toolbox is unavailable says so instead of doing nothing.
  `docs/mcp-agentless-operators.md` documents the minimum attach path (#382, closing #380)

## Bug Fixes

- **plugins**: a plugin's resource lookup stops falling back to the host's copy once unloading starts.
  `getResource`/`getResources` were child-first with a parent fallback, so after `markUnloading` a
  miss quietly resolved against the host - own-JAR resources stay available to teardown code, shared
  paths stay parent-first (`META-INF/services` is non-shared even for a shared interface), and a
  post-ACTIVE miss returns the standard null/empty with one WARN per distinct name and DEBUG for
  repeats. The diagnostic is wrapped, because logging during shutdown must not replace a missing
  resource with an exception on the teardown thread (#325)
- **browser**: navigation callbacks handle a frame that is already closed. `NavigationPageInjection`
  acquires the main frame on the callback thread - acquiring it later could name the *next*
  navigation - and dispatches only the follow-up, invalidating before even a failed or absent frame
  lookup so a previous document's job cannot report its PID for this commit. Empty and `about:blank`
  commits refresh the PID too, or a dashboard retains a heavy page's. A PID failure no longer discards
  the page helpers, and closed transports are recognised as closed rather than as errors (#400)
- **panels**: nested panels in the right dock get their explicit width constraint back. `c15660c5`
  wrapped them in a `PanelColumn` whose `Box(weight(1f))` lacked `fillMaxWidth()`, and the loose
  constraint let `SubcomposeLayout` cache stale bounds across a resize, so `Row` content after a
  weighted `Spacer` disappeared (#398, closing #278)
- **ui**: quick actions stop vanishing in a short tab rail. `MeasuredRailHostActions` measures the
  rail even while the actions are hosted elsewhere, so growing the rail can reclaim them - the
  fallback is reversible rather than one-way - and the per-rail action budget is applied against the
  measured height (#328, closing #320)
- **crash**: the crash dialog's scroll boundary is refined and error sanitization is bounded, with the
  input bound documented and expansion ordering verified. A truncation at the message limit can no
  longer leave a partial token exposed (#350)
- **logging**: private hostnames are redacted whatever their case. The existing matcher is
  lowercase-only by design, which left `Proxy.Corp.Internal` untouched and `Acme.corp.internal`
  half-masked; a `.internal`/`.local` pass now runs first, case-insensitively, so a mixed-case leading
  label cannot survive. Both passes preserve ports, which stay useful diagnostics. Case folding also
  masks ambiguous constants such as `Status.INTERNAL`, accepted because free text cannot tell those
  from a private DNS name (#346)
- **plugin-store**: plugin timestamps stop reading as the Unix epoch. `PluginStoreClient.parseTimestamp`
  was a stub returning `0L`, so every plugin in the Toolbox showed "Last Updated" and "Published" as
  1970 regardless of what the server sent. Parsed via `java.time.Instant` - both the Z-suffixed and
  numeric-offset shapes - falling back to `0L` for blank, missing or malformed rather than throwing,
  and matching the field's own empty-string default. `java.time` rather than a second time library:
  the module already uses `java.util.*` in the same source set. Both the list and detail mappings are
  covered, with a timezone-independent fallback (#379, closing #337)
- **language**: `EditorLanguages` (composeApp) and `EditorServiceImpl` (`modules/boss-app-editor`)
  hand-maintained separate extension-to-language tables and disagreed - `.sh`/`.bash`/`.zsh` were
  "shell" in one and "bash" in the other, and the out-of-process copy was missing more than forty ids
  (fortran, delphi, latex, lisp, tcl, clojure, batch, diff and the rest). Both now read a new
  dependency-free `plugin-language-types` module, so nothing extra enters the GraalVM native-image
  build. `EditorLanguages`' public API is unchanged for every extension; `EditorServiceImpl` keeps
  `proto`->`protobuf` and its `plaintext` gRPC default as local additions rather than folding them
  into the shared table (#358, closing #75)
- **editor**: `writeFileContentSafe` catches the errors it is named for. `StackOverflowError` is an
  `Error`, not an `Exception`, so it went straight through the guard, out of the `editor_write_file`
  MCP handler and to the caller as a bare `StackOverflowError` - and the warn that would have named
  the file never ran, which is exactly the missing diagnosis two independent reports complained of.
  `StackOverflowError` and `OutOfMemoryError` are caught explicitly rather than widening to
  `Throwable`, so a `NoClassDefFoundError` still propagates (there is a test). The log names the path
  and the character count, never the content. **This does not fix the write** - whatever recurses is
  upstream of `mkdirs` plus `writeText` - it makes the failure reportable instead of escaping
  (#396, refs boss-plugin-editor-tab#18 and #27)
- **state**: plugin delta state synchronization applies version-checked JSON merge patches, validating
  the delta base before applying and rejecting malformed or deeply nested patches (#361)
- **plugins**: a stale jar is no longer deleted while another plugin's update has it staged. Cleanup
  now requires an explicit intent, staged artifacts survive an unrelated plugin's update, and
  artifacts with unordered manifest versions are retained rather than guessed at. `readDeferredPluginManifest`
  validates a deferred update before recording it, since that path bypasses `installPlugin`: it
  refuses a jar declaring a different plugin id, and refuses a version startup would discard anyway
  rather than promising a selection that never happens (#340)
- **plugins**: two call sites asked "restart dependent plugins?" before checking whether an unload was
  going to happen at all, prompting about an unload a deferred update was never going to do (#352)
- **kernel**: out-of-process plugin reaping is hardened. `reapDepth` (an `AtomicInteger`) replaces the
  boolean flag, so two JVM shutdown hooks cannot clear the in-progress signal while the other is still
  reaping; `reapChildren` unregisters reaped handles from the process-wide `ProcessRegistry`, so dead
  entries do not survive an in-process mode switch; and `OutOfProcessPluginSpawnerImpl.spawn()` stands
  down while reaping, so a plugin load racing host exit cannot register a child after the snapshot.
  `ReapSpawnGate` fences late process creation without blocking shutdown (#365, closing #135)
- **plugins**: loader cleanup completes after a disposal linkage error, so a `LinkageError` thrown
  during dispose no longer leaves the classloader half-torn-down (#302)
- **keymap**: `storedKeyName` folds a captured key through `canonicalKeyName` before persisting it, so
  a rebind is indistinguishable from a preset binding - same match, same signature, same rendering,
  and deterministic across a cold and a warm toolkit. Existing keymaps are handled twice deliberately:
  `canonicalKeyName` resolves a stored keyCode so an unmigrated file keeps matching, *and* the
  migration rewrites the file, because a keymap restored from a backup or copied off another machine
  reaches the matchers before it reaches the migration. The repair runs before `migrateSettings`'
  chord arithmetic, which is what finally lets #322's drop-on-conflict guard see a UI rebind at all.
  The capture dialog's preview renders the exact `KeyStroke` that Apply persists, and modifier-only
  captures are rejected (#335, closing #329)
- **keymap**: the Shortcuts screen's own tester stops reporting working shortcuts as broken.
  `validateKeyName` kept a fourth hand-written copy of the key vocabulary, the only one nothing
  tested, and it had drifted: fifteen keys the interceptor dispatches were reported as "Unknown key
  name" on a shortcut that fires - every function key F1-F12, Home/End/PageUp/PageDown, the character
  spellings ("-", "=", "/") which drew the confident and wrong advice "Key name should be 'Minus' not
  '-'", and the cold and glyph spellings Compose renders. It reads `isKnownKeyName` now, and an
  unrecognised name is a note rather than a FAILED, because "will this key match" is not knowable from
  the name alone. A key stored as a raw packed keyCode keeps FAILED - that one *is* decidable, and it
  is decidably broken (#376, closing #375)
- **plugins**: the signature sidecar backfill added in #101 usually did nothing, silently. The drain
  was one-shot and triggered by the first non-null session token, which a returning user emits before
  the only path that enqueues has run - so it polled an empty queue, burned a process-global flag, and
  logged nothing, looking exactly like success. Queued items were also dropped rather than deferred,
  since `stillNeedsSidecar` skipped any plugin with an update check in flight and
  `scheduleBackgroundUpdateCheck` raises that flag one line earlier. `maybeDrainSidecarBackfill` is a
  Mutex-guarded drain safe to call from anywhere, triggered by the enqueue, the token handler and the
  update check's own `finally`, with in-flight entries re-queued (#347, #401)
- **plugins**: a genuine signature mismatch stopped retrying forever. `getDownloadUrl` is not
  read-only - it books a `plugin_downloads` row that feeds the store's default ranking - so a settled
  "no signature" answer is recorded in a `<jar>.nosig` marker keyed on the full
  `pluginId|version|sha256` anchor, self-invalidating the moment any of the three changes and deleted
  alongside the sidecar. `downloadOnly` plugins are no longer signed on the download path (the
  microkernel runtime is the only one, and it never reaches the loader's signature check), two sidecar
  deletes are gated on the jar delete having succeeded, and the second full SHA-256 pass at startup is
  replaced by a size and mtime stamp taken beside the first hash (#401, closing #108)
- **plugins**: `PluginSignatureSidecar.write` stages through a unique temp file - two writers racing
  one jar shared a fixed `<jar>.sig.tmp` and could interleave into a half-written sidecar, which is a
  present-but-invalid signature and so a *harder* failure than the missing one it replaced. And
  `read` drops its `exists()` pre-check, a time-of-check-to-time-of-use race against
  `Files.move(REPLACE_EXISTING)`, which transiently unlinks the target on Windows: a reader that
  passed the check could reach `readText()` after the unlink and throw out of a function every caller
  treats as total, failing a plugin load for a reason that had nothing to do with the plugin (#401)
- **plugins**: `SystemPluginManifestService.startSync()` waits on `SupabaseConfig.isInitialized`
  before touching the client. Both of its launched coroutines previously ran before initialization
  finished, so the startup fetch logged a warning and the realtime subscription took an unnecessary
  first trip through its backoff loop, every launch. This closes the race rather than compensating for
  it afterwards (#366, closing #370)
- **overlays**: two dialogs stop dismissing to a destructive action when focus leaves the app. Routing
  `BossWindow` content through `HeavyweightModal` made `MemoryPressureNoticeDialog` clear its
  once-per-session notice and restart offer unread on an alt-tab, and made `ScreenCapturePickerDialog`
  cancel the capture request the moment you switched to the window you wanted to share. An internal
  `LocalDismissModalOnFocusLoss` suppresses only the focus-loss path; Escape and the scrim still
  dismiss deliberately (#353, closing #152)
- **overlays**: the toast overlay stops clipping its content at its first-frame size.
  `HeavyweightCorner` measured against `min(initialSize, region)`, so the 432x600 `initialSize` doubled
  as a hard clip - three verbose toasts exceed 600dp, and because the window is content-sized the
  bottom toast's dismiss button landed outside it, unclickable, on the INDEFINITE path where
  dismissing is the only way out. The ceiling is the parent region now, leaving `initialSize` as the
  first-frame placeholder it was meant to be (#354, closing #154)
- **overlays**: `BossPopup`'s `measuredWidthPx` and `anchorPositionPx` are written from `layout {}`
  and `onGloballyPositioned` but read during composition, so an unchanged value still invalidated
  composition from inside layout - a redundant compose-measure-layout cycle per frame for every open
  popup during a window drag. Both writes are equality-guarded. `AnchorBounds` popups that never
  measure report once through `BossOverlayHost.reportUnmeasuredAnchor()` after a grace period (#367,
  #369, from #143)
- **overlays**: the modal card declares `semantics { dialog() }` and swallows clicks with
  `detectTapGestures` rather than `clickable`, so a screen reader announces a dialog instead of a
  button; the scrim dismiss moves the same way, so `IsDialog` is not merged under a clickable ancestor
  (which crashed the modal). The scrim's dismissal callback refreshes after recomposition (#367)
- **plugin-ui-core**: `BossOverlayHost.useHeavyweightOverlays`, `modalRenderer`, `popupRenderer` and
  `diagnostics` are public mutable statics the KDoc calls host-owned and write-once, on a singleton
  shared with every in-process plugin - and nothing enforced it, so one plugin line could reinstate
  the occluded-dialog bug the file exists to fix. Each locks to its first write via a custom setter,
  leaving the JVM descriptor (and so api binary compatibility) unchanged, and reports a duplicate
  write through diagnostics. `openHeavyweightPopups` is deliberately left alone: it is a running
  counter, and a write-once guard would freeze it at whatever the first popup left (#369)
- **gate**: the plugin load gate reports a successful host update instead of leaving the dialog in its
  pre-remedy state, handles the in-flight download states, retains rollback, reports installation
  progress accurately, and explains the install step that follows the download (#378)

## Improvements

- **plugin-api**: `ApiPackageDivergenceTest` diffs the host's copies of the seven duplicated packages
  (`logging`, `bookmark`, `workspace`, `browser`, `scrollbar`, `ui`, `tab.terminal`) against the
  pinned release jar `plugin-api-core`'s build already downloads, for every public non-synthetic
  member. The three existing `*StableFieldTest`s each pin the one field that has actually bitten us -
  `ComponentLogger.$stable`, which made secret-manager 1.2.6 and 1.2.7 unloadable on every host - but
  nothing covered the general case, where an added method or a changed signature breaks a plugin the
  same way and would be diagnosed from scratch. `ai.rever.boss.plugin.api` itself is filtered out (it
  cannot diverge from itself) and `bundled` is api-only (#368)
- **docs**: `KEYBOARD_SHORTCUTS.md` gains the two things a reader had to find in the source - that
  `AWTKeyboardInterceptor` is the `KeyEventDispatcher` doing most of the dispatching, which is what
  makes shortcuts work while a terminal or browser holds focus, and that there are **two** matchers
  reading one keymap from two different name sources, which is why a chord can work normally and
  report no match in the tester. Plus the accepted key names, since the file is documented as
  hand-editable and said nothing about what a `key` value may contain, and the `Key.toString()` table
  is measured rather than described (#377)
- **docs**: `docs/CLI.md` (options, exit codes, stream guarantees, agent integration recipes) and
  `docs/mcp-agentless-operators.md` (Toolbox kill-switches, attach path) are new; the README's CLI
  section is rewritten around the agent harness (#349, #382)
- **plugins**: `getKeyName` becomes `internal` so the vocabulary tests can read it, with the two
  detekt baseline entries rekeyed for the visibility change and the function unchanged (#335)
- **tests**: roughly fifty new test files, including `BossMcpCliTest`, `McpGovernedInvocationTest`,
  `McpOperationLedgerTest`, `McpPolicyEngineTest`, `McpToolSandboxTest`,
  `McpRiskGovernanceIntegrationTest`, `KeyVocabularyAgreementTest` (all 73 bindable keys, both
  vocabularies read from the code under test), `CanonicalKeyNameTest`, `ShortcutTesterKeyNamesTest`
  (pinned in both directions, so the set cannot be padded into passing), `KeymapMigrationTest`,
  `RemoteUiPlacementTest`, `NavigationPageInjectionTest`, `GuardedWriteTest`,
  `SidecarBackfillCoordinatorTest`, `ConcurrentSidecarWriteTest`, `UnsignableMarkerTest`,
  `ApiPackageDivergenceTest`, `HtmlFileRoutingTest`, `ChromeDensityControlsTest`,
  `PluginStateDeltaTest`, `HotReloadPolicyTest`, `ReapSpawnGateTest`, `EditorServiceImplTest` (which
  had no tests at all) and `ScrimmedModalSemanticsTest`. Several are mutation-checked against the
  pre-fix code (#430)

## Known Limitations

- **The MCP policy governs registry invocation; it does not isolate installed JVM plugins.** Unknown
  tool names default to ALLOW. Persistent rules currently require editing
  `~/.boss/mcp-tool-policy.json` and restarting, there is no automatic quarantine UI, and the fault
  flow withholds all tools until a damaged policy is recovered - keep a backup before recovering one
  by hand. Session trust is process-wide and cleared from the bottom bar's "Revoke MCP session trust",
  so restore the bar if it is hidden (#371)
- **Ledger redaction is bounded and best effort.** It is not a guarantee for a secret placed under an
  arbitrary key name that neither the key list nor the credential shapes recognise (#371)
- **Hostname redaction is still selected, not complete.** The public matcher remains case-sensitive,
  multi-level public suffixes such as `.co.uk` are rejected by the package-name guard, and unlisted
  suffixes and IP literals pass through unchanged (#346)
- **The write guard reports the stack overflow; it does not prevent it.** Whatever recurses is
  upstream of `writeFileContentSafe`, which is `mkdirs` plus `writeText`. What changed is that the
  failure names the path instead of escaping as a bare `StackOverflowError` (#396)
- **Density only changes how much room a bar takes, never whether it is shown.** The Compact
  bottom-bar auto-off was removed in review: it was reachable from the settings-load catch fallback,
  so a transient read error could silently drop the bar and have the next save persist the loss. The
  title bar's 27dp label row is untouched, and the app still does not report its own chrome budget as
  a measured percentage (#305, #239)
- **`fluck-browser` updates apply at the next launch, not immediately.** That is the fix, not a gap -
  an in-place swap leaves every browser tab blank until a full restart anyway (#352)
- **Two of the five duplicate language tables are out of reach.** editor-tab's own `LanguageDetection`
  and BossEditor's lexer registry live in separate repositories. `FileIcons` is deliberately not
  consolidated either: it keys off the raw filename to keep `package.json`, `yarn.lock` and
  `pnpm-lock.yaml` on three different brand icons, and never computes a language id (#358)
- **The vocabulary tests drive the interceptor's table through a hand-written list of key codes**, so
  a key added to that table alone is checked by nothing. Reading the `when` itself would need
  reflection over a private table; this is stated rather than asserted as an invariant that is not
  enforced (#376)
