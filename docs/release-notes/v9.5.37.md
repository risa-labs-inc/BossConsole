# BOSS v9.5.37

**Release Date:** 2026-10-04

BossConsole sharing now starts by itself after sign-in, and remote viewers get a fullscreen mode,
live cursor shapes and better keyboard and menu handling (#1813). A rare macOS startup crash is
fixed (#1780), and pages in fullscreen browser view take keyboard input again (#1814).

## Highlights

- **Automatic sharing after sign-in** (#1813). Once you sign in, BOSS shares its visible windows
  with your own account so you can open them from Live Sessions. It is on by default and can be
  turned off in Settings. Stop sharing pauses it until your next sign-in. It only ever shares BOSS
  windows, never a display or another app, and still needs Screen Recording permission
- **Fullscreen remote viewer** (#1813). The hosted and embedded viewers have a Fullscreen button
  that shows the stream and its controls together
- **macOS startup crash fixed** (#1780). The browser engine's native library now loads before
  macOS starts drawing windows, which removes a rare crash about two seconds after launch
- **Keyboard input in fullscreen browser view** (#1814). A page in HTML fullscreen gets your
  typing again, and shortcuts still go to the tab's own window

## Features

- **sharing**: new "Share automatically after sign-in" toggle under Settings > Sharing, also
  found by searching "automatic", "startup" or "login". A choice you saved earlier is kept, and
  opening a new window does not restart a running share (#1813)
- **sharing**: while you control a shared window, the viewer shows the host's cursor shape
  (pointer, text, resize and so on). Only standard shapes are sent, never custom cursor images
  (#1813)
- **sharing**: sessions are named after the device and each window after its project, for
  example "MacBook Pro · BOSS". The session list shows an E2E badge for encrypted media (#1813)
- **sharing**: the hosted viewer goes back to its session list after Disconnect or a media
  failure it cannot recover from (#1813)

## Bug Fixes

- **sharing**: Tab and Shift+Tab from a remote viewer move focus the way they do locally, and
  right-click menus in shared browser tabs open at the click point without moving the host's
  pointer (#1813)
- **sharing**: stopping a share no longer shows a "Stop sharing" toast (#1813)
- **browser**: a page in HTML fullscreen takes keyboard input again, and a fullscreen window that
  does not have focus no longer takes keys meant for somewhere else (#1814)
- **startup**: on macOS, the browser engine's native toolkit now loads before the window toolkit
  starts, so its memory allocator swap cannot crash a thread that is freeing memory at the same
  time. If something reorders startup later, BOSS logs an error saying so (#1780)

## Improvements

- **mcp**: the MCP access and activity items stay in the bottom bar even when the terminal's
  title-bar menu also shows them (#1813)
