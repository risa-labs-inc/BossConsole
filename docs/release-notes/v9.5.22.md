# BOSS v9.5.22

**Release Date:** 2026-09-22

Two batches. The dev integration (#935, 129 files) is mostly security hardening that runs the whole
depth of the stack - the desktop host, the edge functions and the database - alongside an MCP
operation ledger with a CLI that reads it, persistence that survives quitting, and Home moving into
the Favorites grid. The second (#1425) is new server-side surface: BossTerm publishes each terminal
share to a `terminal_sessions` registry, and a magic-link web page at `cli.risaboss.com` lists the
live ones and opens a share from any browser.

## Highlights

- **Every governed MCP call is written to a hash-chained ledger, readable without a running BOSS**
  (#935). `boss mcp ledger verify | tail | search` reads the local, sanitized ledger off disk, with
  `--json`, `--file`, and filters on tool, disposition and date. The chain detects edits,
  insertions, reordering and removals from inside retained history; it is deliberately not a
  signature, and the report distinguishes the ordinary all-legacy upgrade state from tampering.
  See [docs/CLI.md](../CLI.md) section 5
- **MCP session trust is keyed to the provider the operator approved** (#815). Trust was keyed by
  tool name alone, so approving one provider's tool for the session silently granted the same
  auto-run to every other provider shipping a same-named tool - an unvetted plugin could inherit an
  approval nobody gave it. `trustForSession` now takes the provider with no default, `policyFor`
  matches only the provider that earned the grant, and a section write drops session trust only for
  the `(providerId, toolName)` pairs it changed. Revocation stays name-wide, because over-removing
  trust is the fail-closed direction
- **BossTerm Live Sessions** (#1425). A signed-in BossTerm publishes each share to the new
  `terminal_sessions` table (owner-only RLS, server-stamped heartbeat, stale sweep on insert and on
  heartbeat). The `live-sessions` edge function signs the owner in by magic link from any browser,
  lists the fresh rows with the caller's own JWT, and embeds the share-viewer in an iframe sized to
  the visual viewport so the key bar rides above an on-screen keyboard. Sign-in is two HttpOnly,
  Secure, SameSite=Lax cookies scoped to the function, so it survives reload, new tabs and a browser
  restart, and no script on the shared origin can read the tokens
- **A client can no longer import ciphertext into a row it can decrypt.** `authenticated` held
  table-level INSERT and UPDATE on `public.secrets` and `public.secret_metadata`, so a signed-in
  user could PATCH any ciphertext into their own `password_encrypted` or `recovery_codes_encrypted`
  and read it back decrypted - every value is under one global key, so a leaked dump plus any
  account decrypts every password in it, and an owned row is a padding oracle against the
  unauthenticated CBC ciphertext. Each client table-level grant is replaced by a column-level grant
  on every column except the ciphertext ones. Every legitimate writer is a SECURITY DEFINER RPC and
  is unaffected

## Features

- **`boss mcp ledger`** (#935): `verify` exits non-zero for broken, incomplete or unverifiable data;
  `tail -n` shows the newest records; `search` filters durable history by `--tool`,
  `--disposition`, `--from` and `--limit`. `--json` for machine-readable output, `--file` for an
  explicit ledger path
- **Home is a built-in tile in the Favorites grid** (#933), first position, independent of the
  bookmarks plugin - so the grid is no longer empty with nothing saved, and Home is still there when
  that plugin is absent. The rail keeps its smaller 36dp target
- **Browser printing is wired to the keymap** (`BROWSER_PRINT`). The native page keeps Cmd/Ctrl+P
  when it holds the chord, and a pending AWT release is cancelled so one press cannot print twice
- **The browser zoom badge is opt-in**, under `Settings > Appearance > Browser Zoom`
- **An external `boss://workspace?path=` link is confirmed before its terminal commands run.**
  `boss://terminal?command=` has consulted `DeepLinkOrigin` since #60, but applying a Space types
  each terminal tab's `initialCommand` into a shell and workspace dispatch never passed an origin,
  so an external link started every command in the file with no prompt. The origin now rides on
  `CLICommand.LoadWorkspace` through the cold-start readiness queue to
  `WorkspaceLoadEvent.requiresConfirmation`, and `SpaceLoadApprovalDialog` lists every command
  first. The operator's own `boss workspace`, and Spaces with no terminal commands, load as before

## Bug Fixes

### Search

- **The sectioned global search list highlights the selected row.** The All-category view - the one
  double-shift opens - advanced a loop-mutated var per section and read it by reference inside the
  `items(...)` lambda, which runs after the walk has finished, so the var held the list's total
  count and no row's computed index could ever equal `selectedIndex`. Section starts are now
  computed up front and captured by value, so the highlighted row is the row Enter opens. The flat
  single-category view always worked, which is why it survived

### Persistence

- **A page visited during startup is no longer dropped.** `RecentBrowserPagesManager.loadAsync`
  assigned `data.pages` straight in, and the history bootstrap did the same and then wrote
  immediately, so a visit landing while the read was in flight was lost from the list and from the
  save scheduled for it. Loads merge now, summing `visitCount` rather than taking the newer entry
  wholesale, which would reset a long-lived page to 1. This is the defect #795 fixed for the sibling
  `RecentFilesManager`
- **One slow mount no longer serializes every recent-files mutation.** Deriving the displayed list
  calls `File.exists()` once per entry - up to 20 - and on an unmounted or disconnected share each
  can block for seconds; #795 had put that inside `mutationLock`, so every `recordFileOpen`,
  `removeFile` and `clearAll` queued behind it. The recorded write and the visible derive now take
  separate, never-nested locks
- **A save that interleaves a logout cannot recreate `user_data.json`.** A save that entered before
  logout but acquired `fileLock` after `clearUserData` ran still wrote the logged-out user's
  identity back - a mutex cannot order a caller that already passed it. Saves now capture a
  clear-generation counter before the lock and re-check it inside
- **Debounced recent-files, recent-pages and user-data saves are flushed on exit** (#795
  follow-up). `RecentFilesManager` debounces by up to 5 seconds, so quitting inside that window
  dropped the last recorded entry. The shutdown step blocks until all three writes are on disk
- **Run configurations preserve timestamps and detect empty writes** (#824, #754 follow-up), with a
  concurrency suite covering update-payload integrity and crash-write safety
- **`SettingsServiceImpl` serializes mutations and persists atomically** (#871), with owner-only
  permissions and fail-closed behaviour when the filesystem refuses them

### Plugins

- **A quarantined subtree is given time to settle before it is judged innocent** (#750). Compose can
  already have measure or layout work queued for nodes from the old subtree, so a fault arriving
  within `SUSPECT_SETTLE_MILLIS` (250 ms, about fifteen 60 Hz frames) keeps the same suspect held and
  reports `Settling` rather than releasing it and moving on. The refund is bounded across the whole
  burst by `RenderCrashPolicy.noteSettlingFault`: with enough mounted plugins a full narrowing pass
  outlasts the window, and an unbounded per-suspect refund would make honest escalation unreachable
- **Manifest reads are bounded before signature verification.** `readBoundedManifest` is split out of
  `readManifestContent` so the byte cap is directly testable, `PluginManifestReader.MAX_MANIFEST_BYTES`
  is pinned against `DevPluginArtifacts.MAX_MANIFEST_BYTES`, and both bounded-read suites carry a real
  zip-bomb fixture - a `plugin.json` entry inflating to 1 GiB from a tiny compressed payload,
  asserted rejected within the byte bounds. `LocalPluginRepository` gets the same treatment
- **Dropped protected dev jars and duplicate jar picks are logged** (#781), so a dev jar losing to a
  system or restart-required plugin says so instead of vanishing from the scan silently

### Browser

- **Focused field details are parsed as JSON, not with a regex.** `FormFieldInfoJson` replaces the
  hand-written extraction against the detector's emitted payload

### CLI and deep links

- **Hidden formatting characters are rejected in commands.** `isValidCommand` looked only for
  `isISOControl()`; it now refuses the `Cf` format and Unicode line/paragraph separator categories
  too, including supplementary-plane format ranges reached through a surrogate pair. The command is
  written into a shell followed by one Enter, so keeping it to one visible line is what makes the
  text shown equal to the text that runs

## Security

### Desktop host

- **`atomicWriteText` pins POSIX files to owner read/write (0600)** (#860) rather than inheriting a
  permissive umask, and fails closed when a filesystem advertises POSIX permissions but refuses the
  restriction. Dashboard stats and project writes migrate onto it
- **Browser URL log lines carry scheme, host and path only** (#691). "Browser created via
  BrowserService" logged a tab's full URL at INFO on every tab creation, hibernation wake and crash
  recovery, and "URL command queued" did the same for every `boss://url` link - and that line reaches
  the Console capture every plugin reads through `logDataProvider`, which the console plugin serves
  to MCP clients through `console_tail` and `console_search`. An OAuth code, a sign-in token or a
  presigned signature went with it. `LogSanitizer.describeUri` hid 12 of 14 credential-bearing URL
  shapes measured, against `maskUriParams`'s 4. Deep links are logged by shape for the same reason
- **JWT tokens are redacted from Supabase realtime log lines** (#855)
- **MCP argument sanitization masks the credential in an `Authorization` header**, not just its
  label, absorbing repeated or arbitrary schemes and reaching a quoted value so a compound
  credential cannot survive
- **Orchestrator snapshot paths are confined** (#873): symlink escapes are rejected and snapshots
  persist atomically with owner-only permissions
- **The Chromium engine's GitHub backup download is verified against the catalog sha256** (#798
  follow-up). The backup runs precisely because the primary source is already misbehaving, and its
  archive is extracted and then executed as the browser engine, so it is the download that needs the
  check most - it was built with `sha256 = null`. The release pipeline publishes one artifact to both
  sources, so the catalog hash binds the backup's bytes exactly as it binds the primary's; a genuine
  difference now fails loudly and falls through to the next candidate. With no catalog hash at all,
  the backup stays unverified exactly as before
- **System-plugin GitHub installs are pinned to build-owned repositories.** `github_repo` reached
  `downloadSystemPluginFromGitHub` verbatim from the remote table, and that path verifies no checksum
  and no signature - only non-emptiness - so a rewritten or maliciously added row could point the
  host at any repository. `pinnedGithubRepoOrNull` fails closed: installable only when the plugin id
  is one this build ships and the repository matches the pin, case-insensitively and with no
  surrounding whitespace

### Server-side

- **`POST /passkey/auth/challenge` is enumeration-safe and rate-limited** (#769). The route runs with
  `verify_jwt=false` and returned three distinguishable outcomes for an email probe: 400 "User not
  found", 400 "No passkeys found for user", or a 200 whose `allowCredentials` handed each stored
  credential id to an unauthenticated caller. Migration 20260910000000 already called this lookup an
  "unauthenticated-grade enumeration oracle for the whole user base" when it revoked
  `find_user_by_email`'s client grants; the oracle survived over HTTP. Every pre-auth failure now
  returns the same inert challenge - a fresh random value that is never stored, so `/auth/complete`
  can never verify against it - with an empty `allowCredentials`, identical in status, shape and
  content for every email tried. 20 challenges per client per hour, 429 documented in the OpenAPI
- **The passkey SECURITY DEFINER set has a closed `search_path`** (#773), including the nested-trigger
  regression, with passkey cleanup semantics preserved under it
- **Client ciphertext writes are revoked** on `public.secrets` and `public.secret_metadata` (see
  Highlights). The migration reads the column list from the catalog, never grants a privilege a role
  did not already hold, and aborts if protected columns remain writable through inherited grants
- **The `live-sessions` function requires `LIVE_SESSIONS_PUBLIC_BASE_URL`** with no
  `X-Forwarded-Host` fallback (caller-controlled, and a non-allow-listed `redirect_to` makes GoTrue
  silently fall back to the desktop deep link); `/api/otp` answers 503 without it, refuses
  `Sec-Fetch-Site: cross-site`, and does not create accounts. Rate-limit keys prefer
  `cf-connecting-ip`, else the rightmost `X-Forwarded-For` entry, since the leftmost is
  client-chosen. Opened share links carry a fixed `from=live-sessions` marker rather than a URL, so
  the viewer cannot become an open redirect

## Improvements

- **MCP tool schema parsing is cached** (#867), bounded to 128 entries with schemas over 64 KiB
  bypassing retention, so reloadable plugins cannot grow the cache without limit. IPC callers can
  only read the registry and cannot add keys
- **`cli.risaboss.com` fronts the live-sessions function** through a Cloudflare Worker on a Workers
  Custom Domain, so cookies carry `Path=/` and the magic link lands on the vanity host. The alias
  redirect keys on `Host` only (`X-Forwarded-Host` is gateway-rewritten and loops), carries an
  `_alias=1` loop breaker, and goes through the shared response helper so security headers apply
- **CI**: the edge-functions workflow now checks `live-sessions` and `redirect`, and database
  regressions run through `supabase test db`, including `client_ciphertext_write_test.sql` and
  `passkey_definer_search_path_test.sql`
- **Docs**: [docs/dev-935-release-checklist.md](../dev-935-release-checklist.md) records the rollout
  checks this batch needs - auditing effective client grants before the ciphertext migration,
  verifying `system_plugins` rows against the build's pins, and confirming the primary and backup
  Chromium archives publish identical bytes. `docs/CLI.md` gains the ledger section

## Known Limitations

- **The ledger's hashes detect tampering with retained records, not authenticity.** No secret key is
  used, so a complete rewrite can recompute the chain and removing only the newest tail cannot be
  distinguished from normal retained history without an external checkpoint. Ledger files are
  owner-only, and `boss mcp ledger` reads local disk - it is not a plugin-facing MCP read surface
- **`atomicWriteText`'s 0600 rule does not apply to every state writer.** The separate
  `writeModeFile` writer for `env_vars` preserves existing permissions deliberately
- **Persisted MCP rules stay tool-name-wide**, unlike the now provider-scoped session trust.
  Narrowing them needs a policy schema and a legacy-rule migration with matching UI semantics
- **Shutdown flush waits for persistence.** A bounded shutdown has to account for blocking
  filesystem I/O; a coroutine timeout alone cannot guarantee a blocked write stops
- **Rolling a system plugin's repository forward now takes a host release**, since the pin is derived
  from the build's `FALLBACK` set. Raising a `min_version` floor or disabling an optional row is
  still a Supabase row edit
- **Browser print is a direct-native exception to the usual AWT ownership rule**, verified by hand on
  macOS. The pending AWT cancellation is best-effort, not a cross-thread exactly-once guarantee; do
  not copy the pattern for destructive actions
- **A site can intercept browser print.** The print script runs in page context, so a page overriding
  `window.print` sees the call
- **The Chromium backup stays unverified when the catalog lookup itself failed**, because there is no
  hash to verify with - unchanged from before this release
- **The live-sessions page needs `frame-src https:`** in its CSP: the embedded viewer's origin is the
  user's own tunnel and is unpredictable per share
