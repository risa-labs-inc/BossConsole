# BOSS v9.5.34

**Release Date:** 2026-10-01

You can now sign in to BOSS with Google or Apple (#1767). This release also brings back the
destination chooser for links clicked in terminal tabs (#1798), and moves the window sharing
status bar below the macOS title bar (#1782).

## Highlights

- **Google and Apple sign-in** (#1767). The login screen has Continue with Google and Continue
  with Apple buttons. Sign-in finishes in your browser and returns to BOSS through
  `boss://auth/callback`
- **The terminal link chooser is back** (#1798). Links and file paths clicked in a terminal tab
  ask where to open again, instead of skipping the chooser
- **Sharing status sits below the title bar** (#1782). The window sharing status row no longer
  sits under the macOS traffic lights

## Features

- **auth**: Google and Apple sign-in on the login screen. It uses a PKCE authorization-code flow
  in the system browser, with no local callback server. A waiting screen lets you reopen the
  browser, copy the sign-in link, or paste the callback by hand (#1767)
- **auth**: on macOS, Apple sign-in opens in Safari, the only browser that offers the Mac's own
  Apple Account with Touch ID. If Safari cannot be opened, BOSS uses the default browser. Google
  always uses the default browser (#1767)
- **auth**: BOSS ignores a sign-in callback it did not start, and a fake callback cannot cancel
  a real sign-in. If you cancel during the code exchange, you stay signed out. A sign-in whose
  callback never arrives expires after 10 minutes. Codes and tokens are never logged (#1767)
- **auth**: on Linux, BOSS registers the `boss://` scheme at startup, but only when no other app
  already handles it (#1767)
- **live-sessions**: the Live Sessions page on cli.risaboss.com also offers Google and Apple
  sign-in. The exchange happens on the server, so no token or verifier reaches page script. A
  spent or expired magic link still shows its own message, not a cancelled sign-in (#1767)

## Bug Fixes

- **terminal**: links that the terminal plugin opens go through the host's destination chooser
  again. Only `http`, `https` and absolute local `file:` links are accepted, and network paths
  are refused. Opening a file link checks the file without blocking the UI thread, and falls back
  to the active pane if the source pane has closed (#1798)
- **sharing**: the sharing status row now appears below the native title bar, after the update
  banner. It clears the macOS traffic lights, and keeps its row when focus mode hides the top bar
  (#1782)

## Dependencies

- **plugin-api**: `boss-plugin-api` 1.0.95 to 1.0.97, which restores terminal link destination
  requests (#1798)
