# BOSS v9.5.20

**Release Date:** 2026-09-16

Two integration batches and one crash containment fix, across 275 files. The theme of the larger
batch is that out-of-process work stopped trusting whoever can open a connection: the microkernel's
IPC transport now pins its certificate and authenticates every caller with a per-instance
credential, the filesystem and terminal services are host-only and owner-scoped, and the logs their
children write fail closed rather than falling back to an unprotected directory. The second batch
gives plugin development a CLI of its own - `boss plugin init`, `validate` and `link` with dev hot
reload - alongside `boss doctor`.

## Highlights

- **Every microkernel IPC call is authenticated, and the transport is pinned** (#776). The channel
  pins the server certificate and authenticates callers with per-instance bearer credentials;
  `connectToService` no longer opens unauthenticated peer connections, so an absent service returns
  null and a known service without a delegated credential fails explicitly. Revocation invalidates
  an old process instance including its idle streams. This is not mutual TLS and not an OS sandbox:
  code running with the user's OS privileges can read process environments, which is why unrelated
  subprocesses must not inherit the IPC credentials. **It is a paired release** - see
  `docs/authenticated-ipc-rollout.md` and the Known Limitations below before deploying either half
  on its own
- **The filesystem service is host-only, and refuses before it learns anything.** Every RPC calls
  `IpcCall.requireHost()` *before* logging a path, validating it or touching the disk, so a refused
  caller gains no path-existence information and never gets its supplied path into a log or an
  exception. Watch collection checks authority at registration and again on every emission, so a
  revoked credential stops a live watch. Scans are depth, count and response-byte bounded, reads
  are paged, and path validation resolves existing ancestors before read, create, write or watch
  while rename and delete operate on the final directory entry without following its symlink
- **Plugin development has a CLI and a hot-reload loop** (#468). `boss plugin init <name>` scaffolds
  a Gradle project, `boss plugin validate <path>` checks the manifest and bytecode, and
  `boss plugin link <path>` stages the jar into `BOSS_HOME` with hot reload. Documented in
  `docs/PLUGIN_LAUNCHPAD.md`; a system plugin or one that requires a restart is never superseded by
  a dev jar, whatever its modification time
- **`boss doctor`, and health in `boss status --json`** (#579, refs #418). An additive `health`
  object built from state BOSS already keeps - sandbox watchdog disables, plugin health rows, a
  browser engine that is missing, failed or unresponsive, and MCP kill-switch and policy faults.
  `boss doctor` prints the same report, one line per finding with a suggested next step, and exits 2
  while anything is reported. Neither command changes anything
- **A stale Supabase realtime rejoin no longer kills the app** (#784). supabase-kt 3.8.0 can resume
  `scheduleRejoin` during the socket reconnect delay, whose unsubscribe then reads the cleared
  socket and throws `IllegalStateException: Websocket not yet initialized`. The separate reconnect
  job recovers on its own, so that stale attempt must not reach the crash dialog - dismissing which
  exits BOSS

## Features

- **Plugin Launchpad** (#468): `PluginScaffolder`, `PluginValidator` and `DevPluginReloader`, with
  `boss plugin init` / `validate` / `link` registered in the CLI, the headless gate and all three
  launchers. Hot reload is symmetric for a plugin that was switched off: a forward reload of a
  plugin with `wasEnabled = false` installs disabled and treats `DISABLED` as success, the same
  holds when the active user lacks RBAC access for it, and rollback reinstates the previous jar in
  `DISABLED` state without uninstalling. Staged jars resolve with manifest identity validation, the
  way startup already does
- **`boss doctor` and `boss status` health reporting** (#579). `partial` is additive on the wire, so
  an older CLI against a newer BOSS and the reverse both still parse: `unchecked` still means
  nothing could be read at all, while `partial` says an area was read from several sources and some
  failed, so the findings are real but do not cover it. `boss doctor` prints a "Partially checked:"
  line and stops saying "No problems found."
- **Bitwarden JSON and KeePass XML imports.** The Bitwarden unencrypted JSON export
  (`Tools > Export vault`) and the KeePass 2.x plaintext XML export
  (`File > Export > KeePass XML (2.x)`) are both read now; the encrypted `.kdbx` needs the user's
  master key and stays out of scope. Both formats are sniffed *before* the HTML and CSV branches,
  because their markers are unambiguous, so an export saved with an odd extension is still read
  correctly. Empty passwords are rejected and whitespace-only ones are not: whitespace can be the
  original credential, so password values are never trimmed
- **Process log infrastructure that fails closed** (`boss-process-manager`). Setup refuses before
  spawning when the log root crosses an unapproved symlink, the filesystem cannot provide persistent
  Windows ACLs, or the native platform is unsupported - no child is started with unprotected
  fallback logs. Each process id shares one rotating writer across overlapping generations, and
  creation, rotation and permissions operate on held directory handles rather than reopened child
  paths
- **A native file module** (`boss-native-files`), giving directory-handle-relative POSIX and Windows
  operations where names are single components and never followed as links, so an opened directory
  remains the same object even if it is renamed by another process of the same user
- **Private IPC state is owner-instance scoped.** `StateService` derives the owner from the verified
  caller rather than a self-declared `sourceProcess`; a replacement instance may overwrite its old
  key but cannot read the previous private value, nor obtain it through an optimistic-version
  conflict response. Terminal sessions and retained exit output are owner-scoped too, with HOST able
  to administer all sessions and SUPERVISOR deliberately not inheriting that authority
- **Spotlight runs the commands it advertises** (#700). `KeymapActions.getAllActionIds` offered 48
  ids to the search catalog while `onCommandSelect` handled 22; the other 26 fell through a bare
  `else -> {}` and silently did nothing. Eighteen of them already had a `MenuActionsHandler` route
  and are now dispatched; the remaining eight - the editor verbs and the debug external-link entry -
  have no safe host route and are named as unsupported rather than failing quietly
- **Plugin registrations follow window lifetimes.** MCP and search providers, panel menus, settings
  pages, deep-link actions, shortcut providers and status-bar items route through
  `WindowRegistrations`: the newest window's registration serves every window, and unregistering it
  restores the newest surviving owner, so disabling in one window leaves another window's
  registration available

## Bug Fixes

- **Stale realtime rejoin crashes are contained** (#784, BossConsole-Releases#28). The rule matches
  the throwing getter and retry path specifically - the exact `IllegalStateException` message plus
  the first four frames, copied from the report rather than inferred - so an arbitrary
  initialization error or an application's own pre-connect `unsubscribe` still surfaces. The
  regression test drives the installed SDK's actual delayed retry, so an SDK fix or a stack change
  forces this narrow rule to be re-evaluated
- **The update prompt no longer stacks on top of another modal** (#696). On the heavyweight-overlay
  path every modal is its own always-on-top window, and two of them stacked is the state that left
  BOSS unusable. The prompt can appear on its own timer, so it now yields to any other heavyweight
  modal in any BOSS window: it does not open over one and steps aside when one opens over it, with
  the update banner still visible and the prompt reappearing once the other modal closes
- **Run-configuration disambiguation works on Windows** (#653). `makeNamesUnique` and
  `makeStoredNamesUnique` split `RunConfiguration.filePath` on a literal `/`, but a stored path is
  OS-native and backslash-separated on Windows, so the `parts.size >= 2` guard never passed and two
  configurations of the same name in different directories stayed byte-identical in the Run
  dropdown. Both separators are handled, the project name comes from the shared path utilities
  rather than `substringAfterLast('/')` - which would have put the whole absolute path into the
  label - the stored rewrite keeps the project bracket it used to drop, and empty segments from a
  doubled separator in a hand-edited `run-configurations.json` are filtered
- **A failed workspace disk operation no longer discards committed state** (#564), and directory
  identity is verified by filesystem identity rather than by a mutable timestamp or two absent
  provider keys. Persistence is constrained to validated local ids
- **The JxBrowser auto-release gate waits for the modules the build actually resolves** (#678, fixes
  #667). The readiness probe checked the core jar and the platform binaries but not
  `jxbrowser-compose` and `jxbrowser-swing`, whose Maven propagation can lag - so when 9.5.1 landed
  the gate passed, a build was dispatched, and every branding matrix job failed at
  `desktopCompileClasspath` with `Could not find com.teamdev.jxbrowser:jxbrowser-compose:9.5.1`
- **Piped CLI output is written as UTF-8** (#604)
- **One window's failing health source no longer hides another window's finding.**
  `WorkspaceHealthSources.pluginSnapshots()` mapped every registered window in one expression, so a
  single source that threw turned the whole plugins area into `unchecked` - and a watchdog-stopped
  plugin in window A disappeared whenever window B's source failed, which is exactly the case the
  feature exists to report. Each window source is contained on its own, every snapshot that could
  be read is kept, and failures are counted and logged
- **A disabled plugin is not reported as a watchdog failure.** Sandbox disabled state alone is not
  evidence of one: operator disable and failed registration set it too. `pluginHealthSnapshot`
  derives watchdog stops only from otherwise healthy rows and shares that set with row decoration
  and the CLI findings, and manager errors take precedence over disabled state so a failed
  registration stays visible
- **The sign-in brand panel's browser view no longer runs on a process-lifetime scope.**
  `BrowserViewState` was handed a `MainScope()`, which outlives the composition that created it; it
  now gets a supervisor scope parented to the composition's own job, with an exception handler, so a
  native view failure is logged rather than escaping into the sign-in screen's other work
- **The bottom bar stays composed while a terminal setup session needs a home**, because that
  status-bar item also hosts the reopened setup dialog. This is temporary chrome visibility and
  never a change to the user's appearance preferences
- **Unbounded per-request state in the mastery and repair services is bounded.** Definition,
  execution and history counts are capped, and a failure report's hints, patterns, messages, stacks
  and sources are truncated to ceilings sized against the default gRPC receive limit, so one report
  cannot multiply into unbounded analysis and retained state. A dead repair adviser no longer
  terminates the collector responsible for later process failures
- **Plugin store metadata and downloads are more careful:** ISO timestamps parse consistently across
  the list and detail payloads, and the download cache is local and hash-verified, addressing exact
  ids and versions by SHA-256 with an initialization failure retained rather than blocking
  repository construction
- **`LogSanitizer` redacts URL userinfo**, in URIs and in free text, without broadening the
  hostname matcher or losing diagnostic ports

## Improvements

- **CI is measurably faster, from a measured baseline.** `docs/CI_PERFORMANCE.md`
  records the eight runs the changes were sized against, states what the Actions API can and cannot
  distinguish (queue wait is not capacity wait), and lists each change: superseded PR runs cancel
  independently per workflow, `test build` is submitted in one Gradle invocation on every OS with
  `--continue` and always-uploaded reports retained, the compatibility tasks are combined, and the
  native-file push matrix runs on integration branches with feature-branch validation on PRs
- **Three new boundary workflows** - `authenticated-ipc.yml`, `filesystem-limits.yml` and
  `native-file-boundaries.yml` - so the authorization, limit and native-path guarantees above are
  exercised on their own rather than only inside the main build
- **`FileSystemDataProviderProxy` reads are paged**, with the paging boundary pinned by a test
- **Plugin publishing moved from shell to Python** (`scripts/publish_plugin.py`), with
  `PublishPluginTask` covered by unit tests and a publishing-regressions workflow
- **The event bus documents what it is.** It is an authenticated broadcast whose source identity is
  host-verified and whose subscriber labels convey no authority; sensitive private state belongs in
  an owner-scoped service, not an event payload
- **`modules/boss-service-filesystem/AGENTS.md`** states the authorization rule, the watch
  re-check, the symlink policy and the focused validation command, so a new RPC cannot be added
  without meeting them

## Dependencies

- **BouncyCastle `bcpkix-jdk18on` 1.85**, new, for the IPC transport's TLS identity
- **RE2/J 1.8**, new, for bounded regular-expression evaluation in repair pattern matching
- **The published IPC artifact is now `boss-ipc-1.1.0.jar`**, distinguishing the
  credential-required JVM API from `boss-ipc-1.0.0.jar`; the paired runtime declares
  `minIpcVersion: 1.1.0`. The jar also stops forcing every gRPC class to initialize at
  native-image build time

## Known Limitations

- **The authenticated IPC change is paired with runtime #21 and is not a standalone runtime
  release.** Build and validate both artifacts together: the runtime must package
  `META-INF/boss-runtime/security-contract` and declare a compatible `minIpcVersion`, and missing,
  old, malformed and future transport markers all fail before a child is spawned - do not remove
  that check to make an old runtime launch. A maintainer must assign the minimum supported host
  version and coordinate runtime distribution, because old hosts downloading runtime releases
  directly may ignore a minimum-host field. Roll back a failed deployment as a matched
  host/runtime pair, and note that PR approval does not authorize production publication
- **Key existence is not confidential, by design.** The private-state API returns an empty value
  for an absent key and a permission error for an existing foreign key; watching an absent key
  waits and then fails the permission check if a foreign instance creates it. Terminal ids behave
  the same way - unknown ids return NOT_FOUND and foreign ids PERMISSION_DENIED. An application
  that needs confidential key existence needs a separately specified state-addressing contract
- **Revocation is one-directional.** The host-controller credential a child accepts lives for that
  child's lifetime; kernel-side process-token revocation does not revoke the opposite direction.
  Terminate the child to end it
- **Process logs are host-owned infrastructure, not an OS sandbox.** Drain lifetimes follow the
  owned parent rather than descendant EOF: after parent exit each pipe drains only its observed
  remaining snapshot, at most 1 MiB, and later descendant output is outside this log contract.
  Closing the read end can give a later descendant write EPIPE/SIGPIPE and terminate a native
  descendant that has not disabled SIGPIPE. Retention is bounded per process id, not across all
  distinct process ids
- **The filesystem host guard is not a sandbox against concurrent filesystem mutation**, and
  `FileSystemDataProviderProxy` deliberately has no production construction site: a plugin PROCESS
  credential is refused. Wiring that proxy for plugins needs a separately reviewed path-grant
  design, so do not remove the host guard to make a plugin call succeed
- **The realtime crash containment is narrow on purpose** and pinned to the supabase-kt 3.8.0
  stack, so an SDK upgrade requires re-checking it rather than assuming it still matches
- **The update-prompt gate does not prove #696 fully resolved.** It counts heavyweight modals only:
  native and Settings lightweight dialogs are not counted, and it does not serialize other
  autonomous prompts against each other
- **Per-window action dispatch is not implemented by the registration arbitration.** The newest
  window's registration serves every window, and global access filters still apply independently of
  registration ownership; restoring a shared id re-queries `tools()`/`shortcuts()` on the closing
  thread, so a slow surviving provider can delay that close
