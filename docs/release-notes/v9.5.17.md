# BOSS v9.5.17

**Release Date:** 2026-09-14

Two batches, and the larger of them is the biggest UI change in months: a **Space** is now a
first-class thing you can name, theme, move a tab into, and leave unsaved. Alongside it, two more
kernel IPC bridges require a verified caller, and server-side encryption stops being a pure function
of (plaintext, key) - two users with the same password produced byte-identical ciphertext, which
made any signed-in user an encryption oracle.

## Highlights

- **The product word is "Space", and a Space is a document now.** Every label, menu item, dialog
  title, tooltip and empty state that said "Workspace" says "Space"; the code word stays
  `workspace` everywhere, because the plugin api under `plugin-platform/` is consumed by 33 plugin
  repos and is binary-checked. More than a rename: the eight built-in layouts are **templates**
  that materialise into a real Space on pick (they used to resolve `{projectPath}`, build the tabs
  and throw the answers away, so the Space list still read `{projectPath}` afterwards), a Space is
  identified by its **id** rather than its name, and the layout watcher no longer writes a named
  Space behind your back. Editor semantics: the buffer is dirty until you save, and a save button
  appears in the vertical bar while there is something to save (#284)
- **A tab moves between running Spaces without being destroyed.** A window runs several Spaces at
  once and shows one; `collectAllActiveTabs` already walked the preserved trees so a plugin could
  *see* every tab, but `findPanel`, `getAllPanels` and `selectTabInPanel` read the current tree
  alone, so nothing could act on a tab that was not on screen. `moveTabToWorkspace` transfers
  through `detachTab`/`adoptTab`, so a moved browser tab keeps its page and its playing media
  instead of being rebuilt from config. Clicking a tab from another Space in Top of Mind now takes
  you there, which previously did nothing at all (#284)
- **Two more kernel IPC bridges require a verified caller.** `GitServiceBridge` had no identity
  check on any of its fourteen RPCs: any process able to open a connection to the kernel IPC server
  could read the open project's full history and working-tree status, and could `discardChanges`
  (destroying uncommitted work), `checkout`, `cherryPick` or `revert` against the real repository
  with no credential. `LogServiceBridge` had none on its nine, so the same caller could `watchLogs`
  on the live stdout/stderr of the running process or `exportLogs` for its whole history - a stream
  nothing scrubs for IPC exposure, since it is whatever every log call site in the codebase
  happened to write. Both now gate every RPC behind `authenticatedCallerOrRefuse()`, and the watch
  streams re-check identity on every emission so a revoked token stops a live stream rather than
  only new calls (#635, #645)
- **Encryption draws a random IV, so equal passwords stop producing equal ciphertext.**
  `encrypt_text` called the three-argument `extensions.encrypt(plaintext, key, 'aes')`, which
  pgcrypto documents as an all-zero IV, making encryption a pure function of (plaintext, key).
  Because `create_secret` encrypts server-side and RLS lets a user read their own
  `password_encrypted` back, any signed-in user was an encryption oracle: grouping a dump by
  ciphertext names every set of users sharing a password, no key required. The same applied to
  `recovery_codes_encrypted` and `twofa_secret`. Ciphertext is now `'v2:' || base64(iv ||
  ciphertext)` with a fresh 16-byte IV per call; `decrypt_text` dispatches on the prefix and falls
  back to the zero-IV path, so this deploys without a flag day, and a backfill guarded by
  `NOT LIKE 'v2:%'` is a no-op when partial or repeated (#647)

## Features

- **A BOSS theme belongs to a Space**: entering one re-skins the whole app.
  `WorkspaceManager.loadWorkspace` is the single door every route goes through (the Space button
  and menu, the picker, `WorkspaceSwitch`, deep links, the CLI, a plugin's `WorkspaceDataProvider`,
  both session restores), and it calls `BossThemeController.select` rather than
  `AppThemeSettingsManager.select`, so a Space theme layers over the Settings baseline instead of
  destroying it. Resolution is the Space's own override, then the baked template default, then the
  baseline. Set it from `Options > Space Theme`; plugins read the result through
  `ActiveTabsProvider.workspaceAccents`, `availableThemes`, `setWorkspaceTheme` and
  `workspaceThemeId` (#284)
- **Every Space a window was running is restored, not just the last one.** The session record was
  one `LayoutWorkspace` stamped `last-session`, so a restart brought back whichever Space was on
  screen and silently dropped the rest. `Last_Session_Set.json` is additive and sits beside the
  Spaces; the old file keeps being written unchanged, so a downgrade still restores. The set is
  written only for two or more Spaces and deleted otherwise, under the same single-writer claim
  that keeps two windows from overwriting each other's record, and the active Space is applied last
  so it is what stays showing (#284)
- **Unsaved Spaces are tracked and offered a save button.** `WorkspaceManager.unsavedWorkspaces` is
  keyed per window, because two windows run different Spaces and one flat set would light a button
  in a window with nothing to save. The flag is derived from both halves, so writing the file turns
  it off with no "mark saved" call. The comparison was measured rather than reasoned about:
  `comparable()` strips id, timestamp, name/description and position-renumbered panel ids, each a
  false positive rather than leniency. Split shape, which pane holds which tab and in what order,
  each pane's pinned count and `projectPath` are all compared (#284)
- **A tab can be dropped into any pane at a named position.** `tabBarTargetAt` answered
  `ExistingPanel(panelId)` for any pane but the source, which appended and drew no line, so the
  only way to say where a tab should sit was to move it and then reorder it. The slot comes from
  the same `reorderIndexFor` arithmetic a reorder uses, over the *target* pane's measured rows, and
  a collapsed pane springs open under a dragged tab after 550ms (#284)
- **A pane has one name.** `ActiveTabData.splitPosition` had promised "Left", "Top right", "Pane 3"
  in its KDoc since it was declared and was never populated, so every consumer invented its own
  naming from the saved `SplitConfig` - a different source of truth that describes the tree rather
  than the screen and goes stale the moment a pane is split without saving. `paneGlyphs` is the one
  normalisation the vertical tab bar and the plugin surface share, and it answers for a Space
  running behind the one on screen too (#284)
- **The quick switcher belongs to the Top of Mind plugin.** `Ctrl+Space` dispatches
  `open-quick-switcher` at the plugin and opens its panel; the host's own `TopOfMindDialog` is
  deleted. When the plugin is absent there is deliberately no fallback dialog - falling back would
  hide a missing plugin behind a switcher that looks fine but sees only this window - so the
  keypress offers Install, offers Enable, or names the state (#284)
- **Close any running Space, not only the one on screen.** `closeCurrentWorkspace` cleared tabs
  through `getAllPanels`, which reads the tree being shown, so a preserved Space could not be
  closed from a list that named it (#284)
- **The tools menu shows a scrollbar when it scrolls.** The grid is capped at `VISIBLE_ROWS` and had
  none at all, so a user with more tools than fit saw a block that looked complete. The gate is row
  count against the cap rather than a scroll-state read: `ScrollState.maxValue` starts at
  `Int.MAX_VALUE` until the scrollable has measured, so both `maxValue > 0` and `canScrollForward`
  are true on the first composition and drew a bar under three tiles (#284)
- **`BossColors.accentText` is served to plugins.** `signalText` already existed in the scheme and
  nothing surfaced it, so a plugin tinting an accent-coloured label had only the fill token (#284)

## Bug Fixes

- **Overlays honor RTL and fractional placement.** `cornerPosition` matched alignments against the
  absolute `Alignment` constants, so logical start/end never followed the layout direction; it now
  delegates to `alignment.align` with the direction passed in. `insetBounds` takes its inset off the
  *logical* end, which is physical left in RTL and therefore moves the region's origin too, and the
  quick-actions inset reports from the correct edge. Sizes round rather than truncate, since an
  inset derived as px / density is not integral at fractional scale factors and truncating loses up
  to a unit per axis. The vertical tab bar's drawer slides in from the correct side (#477)
- **`selectedTabId` is scoped to one Space's tree.** It searched every running Space and took the
  first pane whose id matched, but panel ids are unique only within a tree - every Space's first
  pane is called `main` - so with two Spaces running it answered from whichever was searched first
  and named a tab from the wrong one (#284)
- **A plugin's `deleteWorkspace` and `renameWorkspace` stop silently doing nothing.** Both looked
  the Space up by name and then handed `WorkspaceManager` its id, while the manager matches on
  name, so an id matched nothing and both returned normally: no error, and the Space still there.
  The sibling adapter in `services/bookmarks` passes the name straight through and always worked;
  these two are the copy that drifted (#284)
- **A plugin's Space switch carries the project.** `applyWorkspace` restores `projectPath` only when
  handed a `windowProjectState`, and the plugin-facing call passed none, so switching Space from a
  panel left the previous Space's project selected and everything project-scoped - the file tree,
  search, run configurations - went on answering from it. The layout moved and the project did not
  (#284)
- **A save made while on a built-in layout survives a relaunch.** `loadAllWorkspaces` deduped saved
  files against the shipped list *by name*, so a save while the current Space was a built-in wrote
  the built-in's own id and name and was dropped at the next launch in favour of the shipped entry.
  The same line deleted a user's own Space whose name happened to match a built-in, with nothing at
  all to say it had happened. Merging is by id now, and files already on disk carrying a built-in id
  are adopted as distinct Spaces rather than dropped or promoted over the template (#284)
- **A Space's file is derived from its id, so a name can just be a name.** The path came from
  sanitising the display name and the write atomically replaces whatever sits there, so two Spaces
  sharing a name shared a file and the second save destroyed the first layout while both rows stayed
  in the list. That is also why the list said `Code Review (unsaved)`: the suffix was load-bearing,
  not a label. Nothing is renamed on disk - a Space read out of `Code_Review.json` keeps saving
  there - and a rename is now just a write to the same path rather than a write-then-delete pair
  that left the old file behind on failure. `deleteWorkspace`, `renameWorkspace` and
  `importWorkspace` are id-keyed too, each of which had its own duplicate-name failure (#284)
- **Adding a tab marks the Space unsaved.** The layout watcher is a `snapshotFlow`, and
  `BossTabsComponent.tabsState` is a Decompose `Value` read as a plain property, so it registered no
  snapshot read: adding, closing, reordering or moving a tab between panes changed nothing the
  watcher was watching. The consequence is older than the save button - this flow is the only
  in-session writer of `Last_Session.json`, so a tab added was not in the recovery record until some
  later tree, pin or title change happened to trigger an extract. Bounded by a clean exit extracting
  fresh at teardown, and by live browsers and terminals updating their titles constantly, which is
  why a window of editor tabs is where the record went stale (#284)
- **Last Session is marked unsaved, and can be saved out of.** The mark used to be suppressed there,
  reasoning that the watcher keeps the record current - true about the file and wrong about the
  user, and wrong in the state that matters most, since every launch restores Last Session as the
  current Space. It is one app-level slot, overwritten by every window and every layout change, and
  nothing in it is addressable or safe from the next session (#284)
- **Picking a template no longer flashes its theme.** The pick entered the template, applied its
  baked default, then materialised a new Space with a fresh id and entered that, where a fresh id is
  neither a built-in nor an override and fell through to the Settings baseline. The resolved theme
  is written onto the new Space before it is entered. The pick also entered a third Space, and that
  one was avoidable: the menu row called `loadWorkspace` before handing to `WorkspaceSwitch.request`,
  which does the whole job itself - and lied to the switch, which reads `currentWorkspace` as the
  Space being *left*, so pre-setting it skipped the keep-or-close question outright (#284)
- **The Space menu and the switch prompt say "unsaved" too.** The mark lived in one place, and the
  dialog that offers to close a Space is the moment it matters, because that is where the work gets
  thrown away. Verified rather than assumed: Close on an unsaved Space does lose the arrangement, so
  the button reads "Discard and Close" and the old promise that the Space would be "rebuilt from its
  layout next time" is gone, having been true only of a saved one (#284)
- **Key rotation understands the v2 envelope.** `ops/rotate_master_encryption_key.sql` re-encrypts
  raw ciphertext bytes assuming the old zero-IV, no-prefix layout, and a `'v2:'` prefix is not valid
  base64, so decoding raised. A `rotate_ciphertext` helper preserves whichever envelope a row
  already carries, and is a function rather than an inline expression specifically so
  `gen_random_bytes(16)` is evaluated once and reused for both the `encrypt_iv` call and the stored
  prefix - two calls would produce two different values and corrupt the row (#647)
- **`substring(... from ...)` parses.** The SQL-standard trailing `FROM`/`FOR` syntax is recognized
  only on the bare function name, so schema-qualifying it makes PostgreSQL treat it as an ordinary
  call where `FROM` is not a valid argument separator. Caught by hosted CI's pgTAP check, which no
  local run in this environment could reach (#647)

## Improvements

- **The Space button wears a Space glyph.** A briefcase says "work", which is the half of the old
  word that got dropped when Workspace became Space, and it is the same job the Top of Mind footer's
  button does, so wearing different icons made one control read as two. `SpaceIcon` tips a large
  pane beside two stacked ones onto the isometric plane the floors view uses (#284)
- **The Space picker sits above the project picker.** A Space remembers a project, so the Space is
  the outer choice and the project is a property of whichever one you are in; listing the project
  first read as the reverse (#284)

## Dependencies

- `boss-plugin-api` 1.0.89 to 1.0.90, adding the tab-transfer surface (boss-plugin-api#44): eight
  defaulted members on `ActiveTabsProvider` - `supportsTabTransfer`, `liveWorkspaceIds`,
  `moveTabToWorkspace`, `moveTabToPane`, `activePanelId`, `selectedTabId`, `allWindowTabs`,
  `refreshAllWindowTabs` - plus `BossColors.accentText`. A superset of 1.0.89, nothing withdrawn,
  and verified against the published jar rather than assumed: v1.0.89 carries none of the eight
  (#284)

## Known Limitations

- **Only one of the three encryption defects from #618 is closed.** The key truncated to 32 string
  characters instead of 32 bytes is untouched, because a deployed key may be hex or base64 and the
  migration cannot tell which is live in a given project's Vault - guessing wrong makes
  `get_encryption_key()` unusable and breaks encryption for every row on deploy. The missing MAC/AEAD
  needs its own wire-format review. Both gaps are documented in the migration's own header
- **Eleven kernel IPC service bridges remain unauthenticated.** #635 and #645 close the Git and Log
  bridges on top of the Supabase proxy and Download bridges from #550 and the secrets and RBAC
  bridges from #505. The rest still trust every caller
- **Spaces materialised before this release inherit no theme.** Nothing records which template a
  Space came from, so a migration would have to guess from a name a user can also type, and guessing
  wrong assigns a theme nobody chose. They are one right-click away from the right one
- **Destinations for a tab move are live Spaces only.** Putting a tab into a cold on-disk Space
  means serializing it into the saved layout and destroying the component, which is a different
  operation
- **The top bar marks its Space rows but not its button.** With the top bar on, the vertical bar's
  footer is not drawn, so those rows are the only place that window configuration reports unsaved
  work. A save affordance for the top bar is a design change rather than a mark
- **Saving out of a slot produces a name like `Workspace 1788845279`.** Routing the bar's button to
  the naming dialog would need a second save path, and "one save path" is the property that keeps
  the File menu, the bar and the plugin agreeing. The Space menu can rename it
- **The Space picker's tiles draw the saved `SplitConfig`**, so now that the watcher no longer
  writes a named Space, an unsaved split shows as saved for longer
