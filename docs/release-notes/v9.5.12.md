# BOSS v9.5.12

**Release Date:** 2026-09-10

Two more validation batches off `dev` (#455, #463) plus one standalone change, and the theme is
things that failed quietly. A GitHub rate limit could bring BOSS up with no terminal, no browser and
no editor; a plugin MCP tool could return a quarter of a million tokens with no ceiling; an
out-of-process surface with one text field in it received every unclaimed key press whether or not
the plugin had any reason to see one; and TOTP secrets sat in the database in plaintext. No
dependency moved.

## Highlights

- **A GitHub rate limit stopped taking the terminal, the browser and the editor with it.**
  `system-plugins.json` routes the headline surfaces through GitHub Releases, and an
  unauthenticated host gets 60 API calls an hour shared across everything on its egress IP - a CI
  runner, an agent VM or an office NAT burns that quickly. `downloadSystemPluginFromGitHub` treated
  the resulting 403, any non-2xx and a release with no matching JAR asset as terminal, logged
  "Failed to download system plugin", and moved on. Those three branches now record the plugin as
  store-repairable with the concrete reason, and a **deferred** pass installs it from the store.
  Deferred is the whole point: `PluginStoreConfig.accessToken` is still null while
  `ensureSystemPluginsInstalled` runs, and the store 403s an unauthenticated caller for any plugin
  with non-empty `requiredPermissions`, which is exactly this set - so an inline fallback would fail
  for the same plugins every launch and look like the fix was in. Repairs go through
  `RemotePluginRepository.downloadPlugin`, so the JAR arrives store-signed even though the GitHub
  path it replaces carries no sidecar, an existing `enabled = false` is preserved, and the
  `minVersion` branch is deliberately **not** marked repairable - reaching around a floor the host
  declared would install the exact contract-breaking JAR the gate exists to prevent (#420, refs
  #399)
- **A plugin MCP tool result is capped at 150,000 characters, and the cut says so.** Every
  plugin-contributed tool was unbounded. BossTerm caps its own 13 built-in handlers, but `shorten()`
  is private and terminal-tab's plugin bridge hands `result.text` straight to `TextContent` without
  looking at its length, so `codebase_read`, `git_diff`, `k8s_logs`, `console_*` and the rest had no
  ceiling at all. A result is re-read as cached prefix on every later request in the session, so one
  oversized answer keeps costing: a single `console_search` measured **234,000 tokens** on a real
  host. The cap goes on `McpToolRegistryCore.invoke`, the one BOSS-owned dispatcher every plugin
  tool passes through, so all three LLM consumers get it. Truncation is never silent - the marker is
  appended after the cut and says the *tail* is gone, because several tools close with their own
  "[504 older matching lines omitted...]" note, which is exactly what the cut destroys. The boundary
  backs off one character rather than landing on a high surrogate, and errors are capped on the same
  terms as successes, since a plugin can return a megabyte of stack trace (#390)
- **An out-of-process surface must declare `wants_keys` before it can see a key press.** KeyEvent
  forwarding was never conditioned on anything the plugin declared, so any remote surface with one
  interactive child widget received every unclaimed key while that child held focus. The mitigation
  that shipped with #51 (the surface itself is not a focus target) closed half the gap, and
  `RemoteWidgetRenderer`'s own KDoc already named the real fix as the additive follow-up. It exists
  now: `UIRegistration.wants_keys`, proto field 8, false for every plugin built against an older
  host. False is the fail-closed answer throughout - `RemoteSurfaceComponent` re-reads it off the
  registry on every host callback, because registration can race a host attaching first, and
  `RemoteWidgetRenderer` **omits the key-forwarding modifier entirely** rather than attaching one
  that declines everything (#441, refs #51)
- **TOTP secrets are encrypted at rest.** `twofa_secret` is stored behind a `v1:` envelope with
  auto-encrypt triggers and a `safe_decrypt_twofa_secret` that returns NULL rather than throwing on
  a value it cannot read, so the migration is idempotent. The operational scope is stated in the
  migration itself rather than implied: an UPDATE replaces visible rows, not old physical bytes, so
  dead tuples, WAL and existing backups or PITR may retain plaintext. Helper grants are restricted
  and anonymous RPC execution is denied, both asserted in pgTAP; `build.yml` now stages real upgrade
  fixtures so the regression runs against the actual migration chain (#417)

## Features

- **plugins**: the missing-dependency dialog resolves and installs the **whole closure**, before
  installation rather than after. `MissingDependencyInstaller.planFor` walks the store's
  `dependencies` column through `PluginDependencyResolution.installPlan` - dependencies first, each
  plugin asked about once, cycles and a size cap tolerated and logged - and the dialog shows the
  extra ids as a scrollable "Also installs" list. Three properties are worth knowing: the plugin the
  user was asked about is always in the plan and always last, a store that cannot describe a plugin
  contributes null and that plugin is attempted but not expanded, and if it cannot install the plan
  stops before its dependents including the root, because metadata failure is not proof that an
  unknown dependency is optional. The accepted plan is detached from the window, so closing the
  observing window does not abandon later dependencies (#429)
- **remote-ui**: `UIRegistration.wants_keys` (#441)
- **wizard**: the plugin onboarding wizard keeps requirement labels visible at every scale, keeps
  selected styling on required tools, scrolls its completion step instead of clipping it, and
  distinguishes "no tools were selected" from "no tools were installed successfully" - the latter
  now under a warning glyph and an "Installation incomplete" heading rather than a green check
  reading "Installation Complete" (#443)

## Bug Fixes

- **security**: TOTP secrets encrypted at rest (#417)
- **mcp**: plugin tool results capped at 150,000 characters (#390)
- **plugins**: system plugins repaired from the store after a GitHub transport failure (#420)
- **plugins**: a superseded jar a live classloader still has open is no longer deleted.
  `PluginClassLoader.isPathOpenByLiveLoader(path)` plus a `ReconcileResult.deferred` list leave it
  in place to be swept on a later reconcile. A live classloader merely existing is not sufficient
  grounds on its own, because not everything reads a plugin *through* the classloader: pty4j
  resolves its native helper by reopening its own jar by filename the first time a PTY is created,
  so deleting that file out from under a still-open loader breaks the lookup even though nothing
  about the loader changed. `close()` now holds `UNLOAD_IN_PROGRESS` **across** `super.close()` and
  publishes `UNLOADED` in a `finally`, so the reconciler retains the jar while its resources are
  closing and a throwing close cannot pin the file forever. Registration in `allInstances` moved
  below the lifecycle fields, since reconciliation reads them concurrently (#431, closing #72)
- **plugins**: out-of-process process IDs are scoped by window. The spawner is per-window but the
  kernel registry is process-wide, so two windows running the same plugin produced the same id and
  the second registration evicted the first while its child was still alive, leaving that child
  unreapable at host exit. The id is now a bounded SHA-256 over a length-prefixed `windowId` plus
  plugin id, because IPC uses it as a socket filename and full window UUIDs plus manifest ids exceed
  Unix socket path limits; a blank window id keeps the legacy identity for non-window and test
  contexts. Since the id is now opaque, plugin identity for the performance view comes from spawn
  metadata (`BOSS_PLUGIN_ID`) rather than from stripping a prefix off it, and `ProcessHandle`
  results are enriched from the registry instead of replacing it (#449)
- **plugins**: bundled plugins are exempt from store-signature enforcement. They ship inside the
  signed, notarized app image rather than through the signed store, so none carries a `.sig`
  sidecar - flipping `PluginSignatureEnforcement.enforceUnsigned` on would have hard-failed every
  one of them. `PluginBundledTrust` writes a content-addressed `<jar>.bundled-trust` marker, only
  from `PluginStoreSetup`'s bundled-copy step and only right after copying from the trusted bundled
  directory. Binding to sha256 means the marker cannot be forged by plugin content and does not
  survive the file at that path being replaced by something else, and the trust is preserved through
  reconciliation and rollback (#435, refs #102)
- **plugins**: a declared `minApiVersion` is no longer skipped when the API layer has not resolved.
  `satisfiesMinApiVersion` delegated to `satisfiesVersionFloor`, which answers true for a blank or
  unparseable installed version, and `hostApiVersion` reads a system property published only once
  the API plugin resolves - so a check running before then skipped the floor entirely, offered the
  update and installed it, and the loader rejected it on the same floor afterwards. That leaves a
  swapped jar the host cannot load, which is worse than no update: the Toolbox 1.8.4 on BOSS 9.2.25
  failure. It fails closed now, but only when a floor is actually declared, and `hostApiVersion`
  became `() -> String?` so that null (not resolved yet) fails closed while `""` (resolved, no api
  jar) keeps the answer it always gave - otherwise a host with no api jar would have been denied
  every floor-declaring update for the whole session, every session. An unreadable installed version
  gets its own WARN, because it is a property of the host and a withheld update is otherwise close
  to invisible (#395)
- **db**: the secret paging RPCs get a deterministic tiebreaker. `get_user_secrets`,
  `search_user_secrets` and `get_user_secrets_with_shared` all paged on `ORDER BY s.created_at DESC`
  and nothing else. `created_at` is `timestamptz DEFAULT now()` with no unique constraint and
  `now()` is the transaction clock, so every secret written in one transaction shares it exactly and
  the sort key is a partial order. LIMIT/OFFSET then slices an unstable sequence: a tied row last on
  page 1 can land one position earlier on the next call, inside the slice already consumed and
  before page 2's offset, so a full walk returns it zero times and another tied row twice, with
  nothing erroring. A plugin MCP tool walking by offset reports "no secret with id X" for a secret
  that exists. Appending `s.id DESC` makes the order total. A new migration rather than an edit to
  the applied `20260802*` files, each body reproduced verbatim with only the ORDER BY changed and
  diffed mechanically against its source (#385)
- **secrets**: `SecretEntry`, `SecretEntryWithSharing` and `SecretShareEntry` model the organisation
  ownership columns the organisation migration added (`org_id`, `org_slug`, `is_org_owned`,
  `can_manage`, `shared_with_org_id`, `shared_with_org_slug`), which decoding had been silently
  discarding. The concrete bug: an org admin who did not create a secret has `is_owner = false` and
  `access_level = "org"`, a value the client had never modeled, with nothing to tell a caller they
  are still allowed to manage it. `can_manage` is nullable and fail-closed, with a
  `canManageOrDeny` accessor so the reading lives under one name rather than being reimplemented as
  `canManage == true` at every gate (#356, closing #146)
- **supabase**: response decoding is hardened. `supabaseJson` gains `coerceInputValues`, and
  `decodeListRecovering` recovers individual malformed rows for the unpaginated `getSecretShares`
  list, logging counts without payloads and failing if a nonempty response has no decodable rows.
  Paginated secret lists stay atomic, because the pinned plugin API has no raw next-offset field and
  clients advance by returned `data.size`; role and permission lists stay atomic because
  authorization must distinguish an incomplete response from a valid denial. `RestException` is
  sanitized in `sanitizeSupabaseFailure`, and the strict-`Json` guard in `SupabaseWiringTest`
  expands repo-wide (#351, closing #147)
- **browser**: the default chrome setup is applied to every browser BOSS creates, not just the ones
  that happened to get it. `installDefaultBrowserChrome` bundles the suppressing
  `ShowContextMenuCallback` (JxBrowser's built-in Swing menu resolves its position via
  `getLocationOnScreen()` on the EDT and throws `IllegalComponentStateException` if the hosting view
  stops showing) with the page-click popup dismissal, and it now runs for popup windows, the auth
  brand site, the passkey view and the cross-device manager too. `close()` is called from a
  `finally` on a JxBrowser thread and can itself fail, so it is wrapped - an escaping exception
  there would be exactly the uncaught off-EDT throw this file exists to remove. A fatal setup
  failure releases the managed profile rather than leaking it (#445)
- **updater**: an unsupported-macOS refusal is remembered and its download cleaned up. An
  intermediate release can no longer erase a newer suppressed version, install outcomes are
  published only while that install still owns the state, and downloads, installs and discards are
  serialized across suspension so a refusal cannot delete bytes belonging to a subsequent download
  or a stale request consume a later staged state (#343)
- **crash**: a contained fault is attributed to the plugin it belongs to. A render fault raised
  while the host was inside a plugin call was written to `~/.boss/crash-reports` as
  "(unattributed)". `CrashHandler.attributePluginId` has three ranks and only rank 2 is
  thread-affine - `PluginExecutionBoundary.currentPluginId` reads a ThreadLocal - but
  `recordContained` hands report building to the `boss-contained-crash-writer` thread, where that
  ThreadLocal is always empty, so rank 2 was structurally dead on the whole path. Rank 1 could not
  cover for it (a fault the host caught never escapes a `runAttributed` frame, so nothing tags it),
  and the ladder fell through to the classloader scan, which finds only host frames when host code
  faults on a plugin's behalf. Meanwhile the `writeInline` branch runs on the calling thread and
  read the scope correctly, so one fault attributed differently depending on whether the process was
  about to exit. The scope is sampled where it is valid and passed down; only the scope, since the
  other two ranks key off the throwable and the classloader scan is the expensive step this path
  deliberately moved off the EDT. A captured null is indistinguishable from finding no scope, so a
  genuine host fault stays unattributed (#456, refs #394)
- **search**: double-shift search honours typed case. The exact-case bonus compared the target
  against its own lowercase rather than against what the user typed, so it rewarded uppercase
  characters in the target regardless of the query. Highlight indices also survive expanding
  lowercase now: full-string casing can change length (İ), which invalidates every index, so the
  matcher falls back to per-character casing that preserves UTF-16 positions. Word boundaries gain
  `:` alongside the existing separators, and the per-character `listOf` allocation in the boundary
  check is gone (#453)
- **paths**: `extractParentName` returns an empty string for a bare filename instead of the filename
  itself, and `TabPaths.collapseSeparators` stops destroying roots - a drive root (`C:/`) keeps its
  separator, because `C:` resolves against that drive's working directory instead, and a
  separator-only path never collapses to the empty path. Normalization is applied before
  canonicalization on every platform (#421, #422)
- **urls**: an OS-opened URL with an out-of-range port is rejected. The syntax gate accepted any
  run of ASCII digits, so `:99999` reached the browser; it now bounds the value at 65535 while still
  accepting `:` for the default port, port 0 as a genuine numeric value, and leading zeros in a
  count that would overflow an integer parser (#425)
- **plugins**: a `boss://` URL a plugin asks the host to open is routed through `DeepLinkHandler`
  inside the requesting instance, rather than leaving the process and coming back

## Improvements

- **plugins**: two self-contained pieces move out of the 2,089-line `PluginStoreSetup.kt`.
  `SidecarBackfillCoordinator` was already a standalone class driven entirely by constructor
  lambdas, with zero references to `PluginStoreSetup`'s own state, so its move is a pure file move
  in the same package with no caller or test changed. `isNewerVersion`, `isTooOldForHost`,
  `pickPluginJarUrl` and `extractVersionFromJarFileName` are four pure stateless functions, now a
  `PluginVersionComparator` object. The file drops to 1,894 lines (#448, addressing #447)
- **tabs**: `collectAllActiveTabs`' contract is pinned by test and stated in KDoc - "active" means
  running, not selected or visible, because search, Top of Mind, background-tab metadata lookup and
  pop-out return all need unselected tabs to stay discoverable, and it is not a visibility signal
  for browser hibernation. Panel ids are scoped to their workspace and can repeat across workspaces,
  so a preserved tab's panel id must not be handed to `selectTabInPanel` without restoring its
  workspace first (#438)
- **ipc**: `EventBusServiceTest` awaits a readiness probe before publishing its batch.
  `awaitSubscriberRegistered()` is weaker than the file's own documented pattern - the RPC handler
  running is still ahead of the flow being collected, and `MutableSharedFlow` has no replay, so a
  publish landing first was lost for good. Flaky specifically on the Windows runner, the slowest leg
  (#433)
- **docs**: `AGENTS.md` records how the dependency closure is resolved and consented to, what is
  deliberately out of scope (optionality is not followed across the store, a failed plan is not
  rolled back), and the revised Supabase decoding rules - which lists recover individual malformed
  rows and which stay atomic, and why

## Known Limitations

- **`enforceUnsigned` is still not flipped.** #435 closes the first of the two blockers #102 names.
  The second - sidecars backfilled across the installed base via #101 - only covers the curated
  `system_plugins` list, not every previously-installed store plugin, and whether that backfill has
  reached the fleet is a production-database fact. Flipping blind risks the failure mode the issue
  itself names: the Toolbox becomes unloadable. It remains a one-line flag change for whoever can
  confirm coverage (#435, #102)
- **A store-repaired system plugin becomes active at the next launch, not immediately.** Loading it
  live needs a `DynamicPluginManager`, and those are per-window while `PluginStoreSetup` is
  process-wide, so holding one here would pin a window's manager and its classloaders for the life
  of the process. That is a leak this repo already guards against, and it is not worth introducing
  to save a restart (#420)
- **Optionality is not followed across the store, and a failed plan is not rolled back.**
  `PluginInfo.dependencies` is a list of ids; the `optional` flag lives in the jar's own manifest,
  which is not available before a download the user has not agreed to, so every transitive edge is
  treated as required. A jar declaring a dependency its store row did not is logged, not prompted
  for and not installed - consent was for the list shown. A plan that fails part-way leaves what
  came before it in place, because a dependency installed on its own is harmless and may already be
  wanted by something else (#429)
- **Encrypting TOTP secrets is not secure erasure.** The UPDATE replaces visible rows, not old
  physical bytes; dead tuples, WAL and existing backups or PITR may retain plaintext, and backup
  retention and physical storage reclamation are separate operator decisions. A data-only `COPY`
  restore into a schema with the trigger enabled rejects `v1:` envelopes and needs that specific
  trigger disabled in an isolated restore target for the load (#417)
- **`isPathOpenByLiveLoader` is best effort, not a filesystem lock.** A throwing `close()` still
  publishes `UNLOADED`, so the predicate does not guarantee every OS handle was released; the
  registry is weak, so collectible loaders are not retained by the guard; and a canonical-path
  failure answers false (#431)
- **Six of the eight `PluginStoreSetup` extraction steps remain.** `GitHubReleaseClient`,
  `SystemPluginInstaller`, `PluginSignatureResolver`, `BundledPluginCopier`, the `readPluginManifest`
  relocation and the orchestrator shape all touch the plugin-install and startup-restore paths that
  #447's own acceptance criteria says to verify with a live run (#448, #447)
