# BOSS v9.5.15

**Release Date:** 2026-09-14

A validation batch off `dev` (#626) plus the managed BOSS AI provider, 204 files and the largest
release since 9.5.11. The theme is access that was never granted on purpose: the project's public
anon key could reach the Vault master encryption key, the in-flight login tokens, two audit logs
and the download history, and PostgreSQL's own defaults are what put it there. Alongside that,
shortcuts now fire on key release rather than key press, plugins get a health and recovery centre,
and MCP tool policies can be saved and revoked from the UI instead of by hand-editing JSON.

## Highlights

- **A function in schema `public` is no longer internet-callable the moment it is created.**
  PostgreSQL hardwires EXECUTE to PUBLIC on every new function, PUBLIC includes `anon`, and this
  project's default privileges add `anon` on top - so a `SECURITY DEFINER` function was reachable
  by anyone holding the anon key, which ships compiled into this public repo. Verified on
  2026-09-08: `get_encryption_key()` returned the Vault master encryption key unauthenticated,
  with `decrypt_text()` anon-callable beside it as a decryption oracle over everything
  `encrypt_text` protects; `find_user_by_email()` confirmed any address and returned its uuid;
  `list_shareable_recipients()` returned 152 users with full email addresses to any self-registered
  account. Both obvious revokes are traps in mirror image - `from public` leaves the explicit anon
  grant, `from anon` leaves the hardwired PUBLIC one, and `ALTER DEFAULT PRIVILEGES` cannot remove
  the latter at all - so an event trigger now revokes both on every function created in the schema,
  a one-time sweep covers the ~30 that already had it, and an explicit `grant ... to anon` after the
  create still wins. Anon access must be stated, never inherited.
  `supabase/audit/identity_disclosure_audit.sql` is the standing check, because "we fixed the leak"
  is not a durable claim
- **Shortcuts fire when you let go, not while you hold.** A bound action ran from `KEY_PRESSED`, so
  holding a chord past the OS auto-repeat threshold fired it repeatedly - holding Cmd+N kept
  creating tabs - and the action always ran with the keys still physically down. The interceptor
  still claims a matching chord on the key-down (so it never leaks to BossTerm or a browser while
  held) but only arms it; the action runs exactly once from the primary key's own `KEY_RELEASED`.
  Three follow-up defects went with it: MRU tab cycling wedged open when the modifier was released
  first, a swallowed key-up left a stale arm that silently ate a later unrelated press of the same
  key, and rolling Cmd+N into Cmd+T at speed dropped the first chord entirely (#490, #492)
- **The Vault master encryption key was rotated, and rotation is now a procedure rather than an
  incident.** Revoking access does not un-disclose a key, so it was rotated on 2026-09-09 and the
  184 rows encrypted under it re-encrypted. The scope is stated precisely because the capability was
  worse than the reach: `decrypt_text()` being anon-callable meant ciphertext from any channel - a
  backup, an export, a screenshot - could be decrypted through the API, but no bulk read path to
  that ciphertext existed. `supabase/ops/rotate_master_encryption_key.sql` is kept because rotation
  recurs: one atomic `DO` block, md5 of every row's plaintext captured before and re-derived after
  through `decrypt_text`, and a mismatch or row-count drift raises and rolls back so a broken
  rotation cannot commit
- **A saved MCP tool policy can now be set and taken back from the app.** `setToolPolicy` already
  wrote a durable rule and took effect immediately, but its only caller was the test suite - the
  approval dialog offered "Approve Once" and "Always this Session" and nothing else, so "never ask
  about this tool again" meant hand-editing `~/.boss/mcp-tool-policy.json` and restarting. The
  dialog now offers **Always Allow** and **Always Deny**, and "Persisted MCP policies" in the
  bottom bar lists every saved rule with a per-row Reset to Ask. Revoking removes the key rather
  than rewriting it to ASK (so the count actually drops, and a hardened `defaultMutatingAction=DENY`
  is not silently weakened), clears that tool's session trust in the same call, and reports a failed
  write instead of showing a change that never reached disk. It is host UI only, never an MCP tool
  an agent can call on its own behalf (#469)

## Features

- **Managed BOSS AI**: `supabase/functions/boss-ai` serves multiple configured models through one
  authenticated endpoint. Secret Manager discovers it through the existing authenticated RPC API -
  it requests a single-use ticket, exchanges it at `/auth/exchange`, and gets a five-minute AI
  token; the database derives identity from `auth.uid()` and only the service role can redeem a
  ticket, so no BOSS login token ever reaches the plugin and no desktop host registration or shared
  vault entry is required. Tickets expire after 60 seconds, are stored only as SHA-256 hashes, are
  consumed atomically, and are capped at eight pending per user. Configuration and accounting tables
  are service-role-only; every inference rechecks live per-model permissions and atomically reserves
  usage. Deployment and accounting semantics are in that function's README
- **Plugin health and recovery centre**: a dialog listing plugin health with recovery actions,
  routing watchdog recovery through a safe reload and finishing sandbox teardown before it. Recovery
  reports when it is unavailable, observes sandbox disables, restores panels when a pre-lock
  uninstall is cancelled, and refuses to restart a sandbox for a plugin that is disabled (#454)
- **A missing-dependency prompt is routed to the window that raised it.** The prompt carries a
  best-effort window id resolved from focus at report time, and the bus is now a claim registry
  rather than a channel: every pending prompt is broadcast to every open window and each decides
  independently whether to claim it. A window that is not the right audience leaves it pending
  instead of handing it back, and when the preferred window has closed any other may claim it - with
  the installer re-resolving to a live plugin manager, since installing into a disposed one reported
  success having put the plugin nowhere anything renders (#465)
- **Microkernel Mode is explained before it is enabled**, and the toggle in `Settings > Advanced`
  and the application menu persists `BOSS_MODE=KERNEL` to `~/.boss/env_vars` for the next launch.
  Both in-repo readers of that file now share one normalization (`EnvVarsFormat`), so Settings and
  the runtime gate can no longer state opposite modes for the same file, and the "restart required"
  notice compares against a latched startup snapshot rather than a live read (#481)

## Bug Fixes

- **`completed_authentications` is service-role only.** It holds the freshly minted access and
  refresh tokens for the cross-device (QR) login handoff, and its three anon policies were each
  guarded only by `session_id IS NOT NULL` - which is true of every real row, so all three were
  `USING (true)` written the long way. With `GRANT ALL ... TO anon` that allowed token harvest
  (polling faster than the legitimate desktop wins the race to any QR login, which is account
  takeover), a one-statement wipe of every in-flight login, and session fixation by pre-seeding a
  victim's session id with attacker-controlled tokens. No client reaches the table - the desktop
  polls the passkey Edge Function, which uses the service-role key - so the policies and grants were
  dead code on the live path. Reported as #528; base-table privileges are revoked as well, including
  from PUBLIC, so the gate does not rest on RLS alone (#536)
- **Two audit logs stopped accepting forged rows from any client.** `secret_access_log` and
  `plugin_api_key_logs` both had an INSERT policy of `WITH CHECK (true)` with no `TO` clause, which
  applies to PUBLIC. A row claiming another user viewed or shared a secret could be written at will
  and the table's own SELECT policy then showed it to that user and to every admin as though it were
  real - or a genuine event could be buried under forged entries, which is the failure an audit log
  exists to prevent. The definer RPCs behind them (`log_api_key_action`, `update_api_key_last_used`)
  lost client EXECUTE too, since locking the table alone left the same forgery available through the
  function (#538)
- **`plugin_downloads` is restricted to the server-side pipeline.** `SELECT USING (true)` returned
  who downloaded which plugin and when, plus `ip_hash`, across all users; `INSERT WITH CHECK (true)`
  let any client inflate `download_count`, which drives the store's default ranking, or write rows
  with a forged user id. The stats functions are `SECURITY DEFINER` and bypass RLS, so removing the
  permissive client policies changes nothing for the app (#488)
- **The mobile WebAuthn HTML templates escape their values**, in both HTML and inline JavaScript
  context, against reflected script injection (#546)
- **The secrets and RBAC IPC bridges require a verified caller.** #53 built a process-identity
  interceptor and wired it into one of sixteen service bridges. The two where that matters most -
  the whole password vault and RBAC - trusted every caller unconditionally, so any out-of-process
  plugin that could reach the kernel's local socket could read, mutate or share every secret and
  mint or revoke permission grants with nothing to tell one plugin's calls from another's. Both now
  require an authenticated process id on every RPC, reads included, and refuse with
  `PERMISSION_DENIED` before the provider is reached. Every legitimate plugin already carries a
  credential, so nothing real changes (#505)
- **Saved-secret matching no longer collapses subdomains.** `extractMainDomain` rewrote
  `login.google.com` to `google.com` through a hardcoded list of "common" subdomains and two-part
  TLDs, so a credential saved for one host was offered on its siblings. The full hostname is
  preserved now, with only a leading `www.` removed, and no public-suffix guessing is performed.
  Display labels keep the full hostname too (#482)
- **A hostile download file name cannot throw out of the handler.** `FileNameSanitizer` runs on
  whatever a server puts in `Content-Disposition`. An extension of 301 characters gave a negative
  budget to `take()`, which throws; a name of only dots came back as `download.`, re-creating the
  trailing dot that is invalid on Windows. A Windows device name is now compared at the *first* dot
  as Win32 resolves it, so `CON.tar.gz` is defused, and truncation can no longer manufacture a
  device out of a name that was not one (#540)
- **The plugin update check stopped mis-ordering versions it cannot parse.** `isNewerVersion` split
  on `.` and *dropped* any non-integer segment, shifting every later segment into the wrong
  position. `1.0.0+build.7` parsed as `[1, 0, 7]` and beat the identical installed version, so the
  store offered an update to what was already installed on every check; an installed `1.0-beta.5`
  parsed as `[1, 5]` and beat a genuine `1.2.3`, so the real update was never offered. It now uses
  `SemanticVersion`, the codebase's single comparison primitive - the two disagreed on 32 of 156
  ordered pairs (#539)
- **A cancelled store call is not a network failure**, and every store call now propagates the
  caller's `CancellationException` rather than logging it as an error (#531)
- **Native menu accelerators work on Windows and Linux.** `MenuShortcutBridge` always set `meta` for
  a Cmd binding, which Compose Desktop maps to Super/Windows there, so Ctrl+N and Ctrl+, never fired
  from the menu. The four browser View items (Actual Size, Zoom In, Zoom Out, Reload) are gated on
  `hasBrowser` alongside Back/Forward, since their newly live accelerators could otherwise fire from
  a terminal or editor tab (#535)
- **A cross-window tab selection reaches the target window**, focusing it first and logging a
  warning when that window has closed rather than emitting into a bus with no replay (#500)
- **Focus-mode quick actions stay put** in the collapsed rail while the drawer reveals beside it,
  with rail interaction preserved under the chevron dismissal catcher (#519)
- **The browser's teardown paths are unified** into one idempotent full teardown, closing a memory
  leak when a browser was closed externally (#502)
- **The per-window recent-projects provider no longer leaks.** Window-owned collectors stop at
  disposal, without freezing KERNEL watch streams that are connected to process-wide state (#524)
- **The runner honours the main-panel rerun delay**, and settings it does not support are documented
  as such (#486)
- **A URL whose fragment precedes its query is masked correctly** by `LogSanitizer` (#541)

## Improvements

- **Every project the user opens is announced, not only plugin-initiated ones.** `ProjectChangeEvent`
  was published from `ProjectDataProviderImpl.selectProject` alone, so a path reached plugins only
  when a plugin had asked for the switch. It is announced from the window state's own selection
  callback now, covering the startup restore, the top bar picker, the CLI, deep links and the
  KERNEL-mode gRPC bridge. Project paths routinely contain usernames, so this widens *when* a
  filesystem path reaches every installed plugin - the same install-time gating stance as the rest of
  the application event bus applies
- **`main.kt` is split into modular startup phases.** Around 934 lines came out of one file into
  `CliBootstrap`, `PlatformSetup`, `ChromiumBootstrap`, `OverlaySetup` and `ShutdownSequence`, with
  the extraction's contracts pinned by tests: instance ownership is acquired before the kernel
  starts and released on construction failure, extracted native files are published atomically,
  cancellation is separated from shutdown timeout, and a fully successful KERNEL spawn is logged
  rather than shown as a twelve-second developer-worded toast - only missing JARs or failed spawns
  reach the startup notice queue (#450)
- **`FileIcons` stopped keeping a second copy of the icon extension list.** Its 52-branch gate was
  byte-identical in every branch and carried only a vocabulary, one already declared in
  `LanguageIcons` next door. The copy had drifted: eleven extensions with icons available - `astro`,
  `gql`, `graphql`, `pom`, `prisma`, `proto`, `styl` among them - fell through to the generic
  document icon while the icon sat one file away. All 108 routed extensions are known to
  `LanguageIcons`, so deleting the gate is additive; the 19 deliberate overrides (`.xml` as config,
  `.env` as a lock, `jar`/`war`/`ear` as archives) still win (#525)
- **CI gates the new surfaces.** A `BOSS AI contracts` job runs the edge function's Deno checks and
  tests and the database job requires it; the pgTAP run now generates and staleness-checks its
  access-test suites, and a concurrency script verifies BOSS AI admission across PostgreSQL sessions
- **`composeApp` tests get an isolated home.** Every `Test` task points `user.home` at its own fresh
  `build/test-home/<task-name>`. `ProjectState` keeps only ten recent projects and persists them
  asynchronously, so tests running against the real home could evict entries from a developer's own
  project picker, and a reused test home let later runs race a stale `recent-projects.json`
- **Identity disclosure is scoped to real organisations.** One shared definition of "may this account
  learn who that account is" (`org_visible_users` / `org_is_vetted` / `user_display_name`) is used by
  the Arcade and poker rather than copied, and vetted means a human approved the join - which
  excludes the catch-all `boss` org every account joins on signup, 153 members across 20 domains.
  `list_shareable_recipients` routes through both; it was already org-scoped, which is why it looked
  right, but it accepted *any* shared org. The rule is a set rather than a per-row predicate, because
  as a qual it is pushed below a `DISTINCT ON` and evaluated once per underlying row: 2.7s over 29k
  score rows against 37ms

## Known Limitations

- **A queued MCP approval answered "Always Allow" just after that tool's rule was revoked can
  re-persist it.** Each reset invalidates older authorizations before their final approval boundary,
  but calls already authorized to execute are not cancelled. Closing the remaining gap needs a
  revocation generation compared inside the policy engine's lock
- **Missing-dependency window routing is best-effort, not guaranteed delivery.** The preferred window
  id is resolved from focus at report time, so it can differ from the window whose install actually
  found the dependency; a null target is unscoped by design; and closing a window after its dialog
  has appeared can still abandon that claimed prompt. The Settings window is not a registered
  BossWindow with its own collector, so the consent dialog still opens over the main window
- **Rotation does not reach bytes that are already written.** An UPDATE replaces visible rows, not
  old physical bytes, so dead tuples, WAL and existing backups or PITR may retain data encrypted
  under the disclosed key. The live key differs from it, 184/184 rows decrypt under the new one, and
  the disclosed key opens 0 rows
- **Thirteen of sixteen kernel IPC service bridges are still unauthenticated.** #505 closed the two
  that matter most - secrets and RBAC - alongside the plugin UI bridge that #53 wired. The rest still
  trust every caller
- **Microkernel Mode still applies on restart only.** Nothing re-reads `env_vars` mid-launch, the
  `ConfigLoader` snapshot is taken once per process, and a nonblank `BOSS_MODE` environment variable
  or system property overrides the saved file at every tier. Whether a launch actually works in
  KERNEL mode - spawn, supervision, IPC - remains #391's territory
- **Key-up dispatch has a narrow, documented race.** `dispatchAction` answers both "would this
  dispatch" at press and "dispatch it" at release through one gate, so an action whose gate changes
  in the few hundred milliseconds between the two is decided at release. A matched plugin default
  arms optimistically, since the plugin shortcut registry has no probe
