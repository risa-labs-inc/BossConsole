# BOSS v9.5.45

**Release Date:** 2026-10-16

Plugins now get the dependency versions they ask for. A required dependency's version range is
checked before the plugin activates, and an update that would break a running plugin's range is
refused, instead of a plugin needing 2.x quietly running against 1.x (#1898).

## Highlights

- **Required dependency ranges are enforced** (#1898). A plugin whose required dependency is
  installed at an incompatible version no longer loads, and the error names the required range and
  the installed version. The check runs on every route a plugin can start by, including enable,
  restart and an access grant
- **Updates cannot break running plugins** (#1898). An incoming plugin version that would fall
  outside a running consumer's required range is refused. Optional and disabled consumers do not
  block updates
- **Dependencies start first** (#1898). At startup, required dependencies load before the plugins
  that need them, whatever order they were installed in

## Bug Fixes

- **plugins**: a required dependency at the wrong version is no longer treated as satisfied just
  because a plugin with that id is present (#1898)
- **plugins**: reloading a plugin validates the new jar on disk before unloading the working copy,
  so a version refusal leaves the running plugin in place with a visible error (#1898)

## Improvements

- **plugins**: dependency versions support exact versions, `*`, and whitespace-separated
  comparison bounds such as `>=1.1.1 <2.0.0`. Unsupported ranges and unknown installed versions
  fail closed rather than counting as unrestricted (#1898)
- **plugins**: a missing dependency still raises the existing install prompt; version checks apply
  once the dependency is present (#1898)
