# BOSS v9.5.23

**Release Date:** 2026-09-24

MCP consent gets one home in the bottom bar, with a simpler approval dialog, a per-tool session
trust list and an opt-in YOLO mode, and opening a project now asks one question about where it goes.
On macOS, a startup crash in JxBrowser's native toolkit is closed by loading it on the main thread.

## Highlights

- **MCP access, in one place** (#1593). Revoke session trust, Tool policies and Trusted plugins are
  merged into a single **MCP access** item in the bottom bar, badged in the alert colour while
  session trust is live. The approval dialog asks for a scope once (this call, this session, always
  for this tool, always for every tool from this plugin) and answers with one Deny / Allow pair whose
  labels name the effect, instead of seven buttons across three rows. **Session trust (N)...** lists
  each (plugin, tool) grant with its own Revoke, plus Revoke all
- **YOLO mode for MCP** (#1593). Behind a confirmation, from **MCP access > YOLO mode...** or the
  **Tools > MCP YOLO Mode** checkbox, any call whose policy resolves to ASK runs without prompting.
  It replaces only the prompt: explicit DENY rules, an unreadable policy file, the kill switch and
  RBAC still refuse first. It is in memory only and off at every launch, each call it lets through is
  ledgered as `YOLO_ALLOWED`, and switching it on or off writes a `YOLO_ENABLED` / `YOLO_DISABLED`
  marker. The menu checkbox keeps an indicator and an off switch when the bottom bar is hidden.
  Deployments can refuse it with `BOSS_MCP_YOLO_DISABLED=true`
- **Ask where a project opens: This Space, New Space, or New Window** (#1599). The top bar, Home's
  recent projects, File > Open Project, Clone and New Project each handled this their own way, and
  some then raised a second "Open a space" prompt. They all ask one question now. This Space keeps
  the layout and moves the project in; New Space offers templates, project-free Spaces and this
  project's own Spaces; New Window opens the project in its own fresh Space. The **Default Space**
  setting is still honoured: Ask (the default) shows the dialog, None opens in the current Space,
  and a layout applies as before
- **Startup SIGTRAP race closed on macOS** (#1603). JxBrowser's `libtoolkit` and `libipc` briefly
  unregister the system malloc zone while they load, and a `free()` on another thread in that gap
  crashes the process. Both now load on the main thread before the engine pre-warm starts (about
  6ms), so JxBrowser's own later load is a no-op. Off switch: `BOSS_TOOLKIT_PRELOAD=false`

## Features

### MCP

- **MCP access menu** in the bottom bar, sized to the bar with a new `StatusBarTextButton`. The
  Material buttons it replaces clipped their labels inside the 24-30dp bar (#1593)
- **Redesigned approval dialog**: one scope choice and one Deny / Allow pair. The tool-wide scope
  still says it is keyed by tool name, so it also covers a replacement plugin shipping a tool of
  that name (#1593)
- **Session trust list** with per-tool Revoke and Revoke all (#1593)
- **Session-only YOLO mode**, ledgered and deployment-gated (#1593)

### Spaces and projects

- **One three-way question when opening a project** (This Space / New Space / New Window), routed
  per window. If no window is listening, the request is refused and logged and the project is
  selected directly, rather than a click silently opening nothing (#1599)
- **New Space places the project only once a Space is picked**, so dismissing the list opens
  nothing instead of quietly meaning This Space. A saved Space belonging to another project is left
  out of the list, because applying it would swap out the project just chosen (#1599)
- **Plugins selecting a project through `ProjectDataProvider` are unchanged** and still follow the
  Default Space setting; deep links and the CLI stay outside the dialog on purpose (#1599)

## Bug Fixes

### Browser

- **macOS startup crash in JxBrowser's native toolkit** (#1603). The load used to run on the
  pre-warm thread about 0.5s into launch while the main thread was loading classes. That matches a
  dev launch crash on 2026-09-23 and the 9.2.60 release crash from July. The preload runs only for a
  usable engine carrying the jar's Chromium build, never throws, refuses any library path outside
  the engine directory, and logs every reason it skips, so a crash report can show whether the
  mitigation ran. `libawt_toolkit` is left to JxBrowser because it links `libjawt`

### Tabs

- **Tab previews no longer stick to the pointer after an interrupted drag** (#1473). When a native
  child or the ghost window took the mouse release instead of the source, the drag session was left
  running. A release guard now cancels only that orphaned session, after the source has had its
  chance to deliver the drop, and never cancels a new drag started in the meantime.
  `WindowFocusManager` also exposes live OS focus as a flow, separate from the last-focused BOSS
  window it already reported

### Spaces

- **Plain-shell layouts open without a project and without the warning** (#1592). Terminal +
  Browser and Dual Terminal use `{projectPath}` only to choose where a plain shell starts. With no
  project they already opened in the `~/BossProjects` fallback, but still flashed "Open a project
  first", which read as a refusal and made Home look like it had no project-free split. A layout
  now qualifies by its shape: every placeholder tab is a terminal whose working directory is
  `{projectPath}` and whose initial command is at most `cd {projectPath}`. Agent layouts (Claude
  Code, Codex and the rest) still warn
- **File > Open Project no longer shows the CodeBase panel before the question is answered**; the
  panel opens only when the project lands in this window (#1599)

### UI

- **Tooltips no longer blink under a resting pointer** (#1593). `HoverTooltipBox` computed its offset
  from sizes that are zero on the first frame, so the card could open over its own anchor, end the
  hover, hide, and reappear. It now positions through a `PopupPositionProvider`. The native
  `SwingTooltip` used under hardware rendering clamped itself back onto the pointer at the screen
  edge, and now flips to the other side of the cursor instead

## Improvements

- **MCP call durations are human-readable** in the bottom bar, for example `4m 16s` instead of
  `256100ms` (#1593)
- **Dev batch re-integrated into main** (#1472). It brings no net change in this release: its
  contents shipped in v9.5.22 as #935
