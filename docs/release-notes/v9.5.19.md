# BOSS v9.5.19

**Release Date:** 2026-09-15

One integration batch, 77 files, and its theme is code that was guessing at something it could
have been told. Two-finger swipe navigation now commits on a real macOS gesture release instead of
inferring "the gesture ended" from 120ms of no wheel events; three more kernel IPC bridges require
a verified caller identity rather than trusting any local process; MCP tool policy can be set
before a prompt appears rather than only in answer to one, and the last 100 tool calls are
readable in the app rather than only in a rotated ledger file; and one undecryptable secret row no
longer takes the whole secrets page down with it.

## Highlights

- **Swipe navigation commits on a real CoreGraphics `Ended` phase, never on an inactivity
  timeout.** The recognizer ran entirely inside the page, and AWT does not surface NSEvent's
  scroll phases, so "end of gesture" was literally `GESTURE_GAP_MS` (120ms) with no wheel event.
  That meant holding a completed swipe with the fingers still down navigated anyway after 120ms,
  and the window in which reversing could still cancel was 120ms of continuous motion rather than
  "until you lift". A listen-only session event tap now assigns each finger sequence an id and
  accumulates its final point deltas; the page latches that id while deciding scroll ownership and
  only the matching native release can decide. A stationary hold stays cancellable indefinitely,
  cancelled phases reset without navigating, and momentum - which has no active finger id - is
  ignored rather than re-arming a timer
- **Every RPC on three more kernel IPC bridges requires a verified caller identity**, and the
  run-configuration one is the sharpest of the set: `ExecuteConfigRequest` does not name something
  to read or open, it carries a full `command`, `arguments`, `working_directory` and
  `environment_variables` that went straight to a service whose own KDoc says "Opens a terminal and
  runs the command". Before this it was an unauthenticated arbitrary-command-execution primitive
  reachable by any process that could connect to the server. Identity alone does not close that,
  because an authenticated request still carries the command rather than a reference to one BOSS
  knows about, so `execute` now looks the requested id up in the provider's detected
  configurations and runs that copy, discarding every other field in the request (#634, #666,
  #672)
- **MCP tool policy can be set proactively, per tool and per provider section.** The bottom bar's
  policy button is present with zero saved rules, and its dialog groups registered tools by
  provider with All / View / Edit / Custom / None presets. An Allow needs a second confirming tap
  and shows the tool's risk assessment first, the same way the approval dialog's own "Always
  Allow" does, because it is the same durable tool-name-wide grant (#636)
- **The "MCP: `<tool>`" status line is clickable into an activity log of the last 100 calls.**
  Before this it was the only visibility into MCP activity there was: every call before the current
  one, and the policy decision behind it, was reachable only by opening the rotated ledger file in
  a text editor (#662)
- **One corrupt secret emptied the whole page.** `get_user_secrets`, `search_user_secrets` and
  `get_user_secrets_with_shared` each decrypted `password_encrypted` with a bare `decrypt_text`
  inside a set-returning query, and `decrypt_text` raises on an undecryptable value - so a wrong
  key after a partial rotation, storage corruption or an HMAC mismatch on one row aborted the query
  and the caller watched every one of their secrets fail to load (#668)

## Features

- **MCP section policies** (#636): `McpPolicyEngine.setSectionPolicies` writes a reviewed section
  atomically, checking every prior rule and each tool's and provider's revocation stamp, refusing
  provider DENY and unreadable policy files, and invalidating queued grants and session trust
  after a successful save. Sequential `setToolPolicy` calls would have permitted partial
  application and stale overwrites. These are explicit tool-name rules and not provider trust, so
  a tool added by a later version is not automatically granted. `View` selects tools declared
  read-only except names in the host mutating catalog and HIGH/CRITICAL risk tools; `Edit` selects
  the rest; `None` is a distinct deny-all preset rather than Custom
- **Proactive single-tool rules go through `setToolPolicyIfAbsent`**, not the reactive approval
  path's `setToolPolicy`. The proactive contract is "add a rule only while this tool still has none
  of its own," and the captured `expectedRevocation` cannot enforce that on its own -
  `revocationVersion` only moves on a revoke, so an intervening ASK or ALLOW made through the
  approval dialog never trips it. The new call re-checks `toolName !in rules` under the same lock
  the write takes, so any rule present at write time refuses the write (#636)
- **MCP activity log** (#662): a read-only view over `McpOperationLedger.recentOperations`, scoped
  to calls that actually reached the policy engine. Unsuccessful calls are broken down by
  `McpUnsuccessfulCategory` - denied, cancelled, withheld or failed - through an exhaustive `when`
  over `McpApprovalDisposition` rather than a `setOf` membership check, so a disposition the enum
  grows later is a compile error here instead of being silently counted as a tool fault. Width and
  height follow the originating window, with a fixed-cap fallback before window metadata is
  measured
- **`Settings > Browser > Trackpad` now says why the gesture is not working.**
  `swipeNavSettingsDescription` distinguishes denied Input Monitoring from a run-loop failure from
  a start in progress, and the permission copy covers a fresh install where BOSS is not yet listed
  in the pane at all (use `+` and select BOSS.app). The app only preflights access and never
  prompts for it
- **`boss.browser.swipe.terminals` retains the last 32 terminal records**, semicolon separated and
  published before the next active contact, so a companion consumer can reconcile by contact id
  both before handling a new wheel event and in its watchdog. Reads are non-destructive across
  surfaces; missing or evicted evidence cancels

## Bug Fixes

- **A swipe held stationary past the threshold no longer navigates by itself**, and easing back or
  reversing through zero still cancels right up to the release. Native final displacement
  magnitude is authoritative at release (the page chooses direction), so renderer and native queue
  reordering cannot hide a late easing-back or reversal
- **A gesture that belongs to a nested horizontal scroller stays with the page**, at its interior
  and at either edge, and an unknown canvas or ARIA grid or a scroll chain with
  `overscroll-behavior-x: contain` keeps ownership too. Google Sheets is the explicit exception,
  keyed on private page selectors that fall back safely to page ownership if they change
- **Only a blur targeted at the window resets the detector.** Element focus transfer commits;
  window blur and hidden-document transitions cancel
- **The observer's lifecycle follows the effective setting.** Startup binds observation to it and
  runs native setup, polling and cleanup on a daemon worker off the UI thread. Disabling cancels
  claimants immediately and releases the native source and tap within the bounded run-loop poll;
  a disabled session's callbacks cannot join a replacement session; setup failures release partial
  resources; and run-loop failures cancel the contact, clean up and report a distinct failure
  state rather than reading as denied permission. Availability reads and browser registration do
  not start native observation
- **Disabled and line-mode wheel events avoid host IPC entirely**, and active publication now
  happens once per contact at begin rather than on every movement
- **The project-data kernel bridge had no identity check at all** (#666). Any process able to open
  a connection could watch every recently opened project's path - which routinely contains a
  username - with no credential, and could force an arbitrary window to switch its open project.
  That last one is not only a UI surprise: a project switch publishes a `ProjectChangeEvent` on the
  application-wide bus every installed plugin can subscribe to, so an unauthenticated caller could
  trigger that broadcast on demand. The watch stream captures the identity before collecting and
  re-checks it on every emission, so a revoked token stops a live stream
- **The split-view kernel bridge had no identity check at all** (#672). Any local process could
  drive an arbitrary window's active panel to a URL of its choosing with no confirmation for an
  ordinary http(s) URL, open an arbitrary file path with no confinement through four separate
  RPCs, manipulate panel and tab selection, or overwrite a workspace snapshot under a name it
  picked. Every unary RPC now requires a verified `AUTHENTICATED_PROCESS_ID` and every mutation
  records an attributed audit line
- **A clone's timeout is cancellable** (#660, fixes #641). `GitCloneProcess` streams advisory
  progress while independently awaiting process exit: the pipe reader only queues lines, callbacks
  belong to the awaiting coroutine and settle before return, a failing callback is advisory rather
  than fatal, and a successful exit survives a delayed notification. Progress callbacks must be
  prompt and must not suppress thread interruption, which is now stated on the `expect`
  declaration
- **Spotlight's search state was process-wide** (#593). `GlobalSearchService` was an `object`
  holding the file indexer, the results, the searching flag and the active category, so two
  windows and two project sessions shared one set of answers and reopening the dialog could show
  the previous session's. The index is now owned per window by `SpotlightFileIndexOwner` - one
  path-index pair, so reopening stays warm without retaining a growing collection of projects, and
  replacing the project cancels its scan and clears the old index - while query, results, category
  and selection are dialog-local. Scans belong to the window scope, so closing the dialog does not
  abandon a scan a reopened dialog still needs
- **`FileIndexer` no longer drops a queued scan.** It acquired its mutex with `tryLock` and
  returned early on failure, logging "Index already in progress, skipping", which is wrong once
  callers can share an indexer across dialog sessions. Requests are serialized and queued instead,
  and the scan is cancellation-aware
- **A run failure and a host scan failure had one slot between them** in
  `RunConfigDataProviderProxy`. A replay of the same host error snapshot erased a newer local
  execution failure, and a failed `execute` RPC surfaced nothing at all to the UI. The two now
  have independent lifetimes behind one lock, a failed run reports "Run could not be started." with
  the status code logged rather than exception text, and `CancellationException` is rethrown
  instead of being swallowed by the catch-all in `scanProject`, `execute` and `clearError`

## Improvements

- **`try_decrypt_text` is deliberately not named `safe_decrypt_*`** (#668).
  `ops/rotate_master_encryption_key.sql`'s re-encrypt loop treats every function matching that
  name pattern as a mapped bespoke-format adapter and refuses to run if one is unmapped;
  `try_decrypt_text` wraps the same plain envelope that script already re-encrypts directly, so it
  has to stay outside that sweep. No client role gets EXECUTE on it, matching
  `safe_decrypt_twofa_secret`
- **A null password still fails the whole decode, which is why the SQL `COALESCE`s it to empty.**
  `SecretEntry.password` is a non-null `String` with no default and `supabaseJson`'s
  `coerceInputValues` only coerces a null into a property's default, so a required field without
  one still throws - and because these RPCs return lists, that throw is all-or-nothing. A new test
  pins that, so the reason the migration blanks rather than nulls cannot be forgotten (#668)
- **`BossIpcServer`'s KDoc no longer enumerates which bridges fail closed.** It named two of what
  are now eleven, having drifted stale once already; it points at each bridge's own KDoc instead
- **`SwipeNavParityTest` runs shared sample fixtures through the native reducer and the actual page
  script**, including the host-generated release statement, and pins the cancellation constants
  across both languages. Node is a required test dependency: a missing interpreter or fixture
  fails rather than silently skipping the JavaScript half
- **`docs/review/pr650-followup.md`** records the finding-to-evidence table for the swipe work and
  keeps the required physical macOS checklist visible, rather than treating green automated tests
  as a substitute for a trackpad

## Known Limitations

- **The swipe work still needs physical macOS validation**, and the checklist is written down
  rather than assumed: a stationary hold past ten seconds, release in both directions, easing back
  and reversing through zero, a short flick with a large momentum tail, nested horizontal content
  from its interior and both edges, rapid successive contacts on the browser home surface, and
  slow or fractional drags under browser zoom. At non-100% zoom the native point-based vertical
  threshold can veto a gesture the page's CSS-pixel detector accepts; native rejection is logged
  for diagnosis. These deltas are native CoreGraphics point deltas and not a guarantee of
  CSS-pixel or Compose-unit equivalence
- **One cross-process ordering limit remains.** The cutoff rejects AWT events stamped at or before
  the previous native termination, but cannot identify an old OS event that AWT dispatch stamps
  only after the new contact begins. Arbitrarily delayed dispatch needs real backlog testing
  before a custom FIFO is added between the CoreGraphics tap and JxBrowser's input callback
- **A page can observe the current trackpad gesture token.** The injected bridge exposes the
  process-wide contact id and begin epoch while fingers are down. It does not expose deltas, but a
  page can poll the bridge and infer that a trackpad contact is active. Recorded alongside the rest
  of what an installed plugin or a visited page can observe
- **`SWIPE_NAV_REPEAT_MS` (400ms, same direction) remains conservative.** It is now defense in
  depth against duplicate bridge delivery across a navigation rather than a paused-drag guard, but
  it still means two intentional same-direction requests inside the window can be refused. A
  reversal is held only for the shorter 32ms debounce
- **If Input Monitoring is denied the feature fails closed**, and this path never requests
  permission itself. Granting it needs the System Settings pane, then turning swipe navigation off
  and on to retry - or a restart when the environment variable owns the setting
- **The remaining unguarded kernel IPC services are tracked by #53.** The bridges in this batch's
  own scope are closed; the list of what is left is deliberately not enumerated in
  `BossIpcServer`'s KDoc, since each bridge's own KDoc states whether it requires identity
- **Process authentication is not per-window or per-project authorization.** An authenticated
  plugin may still choose the scan path and target window on the run-configuration bridge, as the
  in-process provider API permits; what it cannot do is name a command
- **The operator-run secret backfill and rotation paths still use raw `decrypt_text` and still fail
  closed**, deliberately. Failing soft is scoped to the three user-facing listing RPCs
- **The MCP activity log is host UI, and staying that way is the stronger guarantee for now.** #416
  tracks moving activity and history into a dynamic plugin; the read surface that needs would have
  to be host-implemented and permission-gated rather than a member on the ungated `PluginContext`
  surfaces, since an ungated ledger read would hand any installed plugin every other plugin's tool
  names, sanitized arguments and error snippets. Retention is finite and best effort - the active
  ledger file plus up to five rotated backups, with a write failure logged rather than retried
- **The Trusted plugins UI lists ALLOW rules only.** A hand-edited provider DENY still needs
  policy-file editing to remove
