# BOSS v9.5.26

**Release Date:** 2026-09-25

A focused plugin-platform fix: dynamic plugins now use the host's own Skia/Skiko rendering runtime
instead of loading a private copy, so rendering objects passed between a plugin and Compose keep
one class identity (#1720).

## Highlights

- **Plugins share the host's Skia rendering runtime** (#1720). Compose passes Skia objects
  (images, layers) to and from plugin code. `androidx.compose.` was already shared with plugins,
  but `org.jetbrains.skia.` and `org.jetbrains.skiko.` were not, so a plugin that bundled those
  classes could define a second copy with a different class identity and a second owner for the
  native library. `PluginClassLoader` now resolves both packages from the host, even when a plugin
  jar ships them
- **Checked against every published plugin before shipping** (#1720). An audit of all 36 plugin
  store entries (`docs/skia-plugin-release-audit.md`) found no dynamic plugin that bundles these
  classes, so no installed plugin changes behaviour. The only artifact that does is the
  Microkernel Runtime, which runs in its own child JVM and is not affected by this change

## Bug Fixes

- **plugins**: share the host Skia/Skiko rendering runtime with dynamic plugins, so a plugin-bundled
  copy can no longer shadow the host's classes or its native library (#1720)

## Improvements

- **plugins**: a regression test builds a plugin jar containing real Skia and Skiko classes and
  asserts the plugin sees the host's classes and resources, and that sharing the renderer does not
  open the rest of the host classpath (#1720, #1721)
- **docs**: added the shared Skia/Skiko release audit, listing every store plugin, its version,
  how it was verified and how many rendering classes it bundles (#1720)
