## 1. Overview & Project Concept

**BOSS** is an open-source desktop workspace for AI agents. It gives agents the tools to carry out plans inside a native desktop environment.

- **Integrations & Neutrality:** Compatible with Claude Code, Codex, Gemini, OpenCode, and 100+ MCP (Model Context Protocol) tools.
- **Components:** Native JVM desktop architecture featuring a Browser, Terminal, Editor, Files, Secrets, and Policy-controlled agent permissions.
- **License:** Apache 2.0 Core.

---

## 2. The Brief: 3 Ways to Contribute

1. **Improve (Core / UX / Performance):**
   - Fix stubborn bugs.
   - Improve performance and responsiveness.
   - Make the browser, terminal, code editor, or navigation more functional.
2. **Extend (Plugins / MCP / Integrations):**
   - Build new plugins.
   - Connect MCP tools.
   - Enhance the developer workflow and introduce new capabilities.
3. **Apply (People / Workflows / Applications):**
   - Create guided experiences and workflows for students, researchers, developers, or operators.

## 3. Contributor Ideas & Benchmarks

Starting points tailored for specific end users:
- **Students:** Project studios, course demo environments, and guided workspace setups.
- **Developers:** Tooling shortcuts, local debugging environments, workflow automations.
- **Researchers:** Reproducible experiments, reference collation, and data analysis workspaces.
- **Operators:** Monitoring, infrastructure scripts, and repeatable task automation.
- **Arcade:** Interactive experiences and plugins built atop the ecosystem.

## 6. Review Criteria (Quality Over Quantity)

Submissions are evaluated on substance, clarity, and testing:

| Criteria | Weight | Details |
| :--- | :--- | :--- |
| **Impact & User Value** | 30% | Practical utility and benefits to users/agents. |
| **Technical Quality** | 25% | Clean code, proper architecture, and stability. |
| **Difficulty & Depth** | 20% | Complexity of the challenge tackled. |
| **Initiative** | 15% | Problem identification and creative execution. |
| **Collaboration** | 10% | Clear communication, documentation, and PR etiquette. |

> **Guidelines:** Avoid duplicate PRs, unreviewed AI code dumps, cosmetic churn, and unprompted sweeping refactors.

## 7. Frequently Asked Questions (FAQ)

- **Who can participate?**  
  Developers of all skill levels worldwide, subject to registration and local compliance.
- **Can I use AI tools to build?**  
  Yes. You are fully responsible for understanding, validating, reviewing, and testing everything you submit.
- **Does my PR need to be merged by the deadline?**  
  No. It only needs to be submitted as a complete, reviewable PR before the deadline. Repository maintainers handle merges independently.
- **Can I submit multiple PRs?**  
  Yes, provided each PR represents an independent, focused, and complete contribution.
- **How do I submit?**  
  Registered participants receive a final submission form link where they provide the PR URL, problem description, and proof of testing.
